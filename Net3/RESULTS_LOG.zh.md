## 全局约定（读任何数字之前先看这一节）

所有实验都跑在 `wq_common.py` 里冻结的三分区基线上，其网络文件是 `models/net3_frozen/Net3.inp`
的冻结副本（导入时校验 SHA-256，所以 WNTR 升级不会悄悄改掉模型）。环境：conda 环境
`water-supply`（python 3.13.12，numpy 2.4.2，scipy 1.17.1，wntr 1.4.0）；`environment.yml` 声明它，
`environment.lock.yml` 保存完整求解结果。缓存在 `baseline_cache/`，其溯源信息在
`baseline_cache/cache_manifest.json`。

约定：`σ = 0.1 mg/L` 是高斯观测误差的**一个标准差**。壁面系数单位是 `m/day`，体相系数 `k_b` 是
`day⁻¹`。

### 推断规则约定 —— 读下面任何数字之前必须先看

本日志中出现三种加权方式，它们**不可互换**：

- **正式截尾高斯似然 —— 主分析。** 所有头条参数、风险和情景数字都用它。它不含任何行为阈值。
- **正式 iid 高斯似然** —— 同上，但把传感器下限的零值当作精确测量值；用来单独分离出"截尾修正
  值多少"（Step 9 和 7b）。
- **非正式 GLUE 评分** `exp(−½(RMSE/σ)²)·1[RMSE<T]` —— **对照组**，保留它是因为草稿用的就是它，
  而且这个对比本身就是一项结果。它**不是**高斯似然：它丢掉了因子 `N = 294`，等价于假设
  `σ_eff = σ√N = 1.71 mg/L`。

### 浓度单位约定（Step 15 修正之后新增 —— 读任何 mg/L 数字之前必须先看）

本日志中每一个浓度都是 **mg/L**，而且现在这句话是真的，不只是写着而已。不管
`options.quality.inpfile_units` 写了什么，WNTR 的 Python API 内部一律用 **kg/m³** 存浓度，所以
换算放在模型边界上做 —— `wq_common.build_model`（入）和 `run_model` / `simulate_chlorine`（出），
别处都不做，这也是为什么没有任何 step 脚本里带 1000 这个因子。与此同时求解器跑在一个
**刻意收紧的容差上，`QUALITY_TOLERANCE = 1e-5 mg/L`** —— 注意单位：和浓度不同，这个量**不做换算**，
EPANET 按文件里的浓度单位原样读入，它比 EPANET 自己 0.01 mg/L 的默认值严格 1000 倍。它是一个
**选定的设置，不是换算结果**（见 §15.2）。**Step 15 之前，同样这些数字是把 kg/m³ 当成 mg/L 读，
即高了 1000 倍**；Step 15 记录了这件事改变了什么、没改变什么，并做了量化。

### 集合的命名

加权**规则**和它产生的**集合**是两回事，把两者混为一谈，一句话就会在"基线配置"和"非正式规则"
之间产生歧义。全文只用以下两个名字：

- **正式似然加权集合** —— 8192 个抽样按截尾似然加权后的集合；所有头条参数、风险和情景数字都
  出自它；
- **非正式 GLUE 行为集合** —— 同一批抽样在非正式评分及其阈值下的结果；只作对照，**从不**作为
  头条数字的来源。

**"baseline GLUE" 这个说法不再使用**：它同时指代了一个配置（`k_b` 固定、传感器无偏）和一个推断
规则（非正式评分），而自从主规则改为正式似然之后，这两个含义已经分家了。要指*配置*就写"基线
模型"，要指*规则*就直接点名规则。

`baseline_cache/` 里**每个持有加权集合的**结果文件都带 `primary_weighting`（或 `weighting`）字段，
`validate_artifacts.py` 会在缺失时报错，所以本日志里的表格不会被误读到错误的规则下。完全不持有
加权集合的那些 —— 缓存清单、预热收敛检验、单参数目标函数曲线、Fisher/剖面几何量、解析已知答案检验
—— 是**按名单豁免**的，而校验器会把豁免名单打印出来，不会默默放行。有两节是**刻意且完全非正式**的，
因为它们的研究对象就是对照组本身：Step 3（答案有多依赖分析者选的阈值？）以及 Step 4 和 Step 5 中被
取代的初步结果。其余地方，非正式数字都与正式数字并列出现，并标注为 *comparator（对照）*。

### 时间约定

168 h 模拟，**120 h 预热**（在 Step 0 里由收敛性检验决定，而不是按惯例定的 —— 但这是一个**有限
时域下的选择，不是收敛结果**，见下文），48 h 评估窗口 `t = 120…168 h`，`N = 6 × 49 = 294` 个残差。
凡是从草稿的 72 h / 24 h 配置沿用下来的数字，出现处都标明已被取代。

### 120 h 意味着什么、不意味着什么

三个氯浓度判据在 120 h 通过。另外两个在模型 168 h 的天花板内**永远不通过**：在 120 h 预热下，
积分亏缺的**周期间残余漂移**仍有 **5.1%**，**水龄** p95 在可得的最后两个周期之间仍变化 **12.8 h**。
所以 120 h 是一个*在有限时域下、使浓度场在给定容差内周期平稳的务实预热长度*，本日志**从不**声称
模型达到了周期稳态，也不声称水龄收敛了。下游一切结论都继承这个限制，这也是为什么基于亏缺的
严重度指标每次报告都要带上这句话（Step 0、Step 10、Step 12）。

### 传感器误差约定（Priority 2 #8）

全文中，"传感器误差 ±X mg/L"一律指高斯**标准差 σ = X**，*不是* 95% 区间，也不是硬性误差上界。
这件事很重要：如果按 95% 带来读，"±0.1 mg/L"就意味着 `σ ≈ 0.1 / 1.96 ≈ 0.05 mg/L`，会把本文
**所有不确定性区间都砍掉一半**（±1σ 覆盖约 68%；±1.96σ = ±0.196 覆盖约 95%）。

给论文方法章的一句话修正：*"本研究中所述传感器误差水平指高斯标准差 σ，而非 95% 区间或硬性
误差上界。"*

## 文件清单与复现方法

本日志中每个数字都来自某个脚本，但都是**手工誊抄**进来的，所以脚本一旦重跑就可能产生漂移。
`validate_artifacts.py` 会拿文档去和 `baseline_cache/*.json` 交叉核对；每次改动后都要跑：

```
conda activate water-supply
cd Net3 && python provenance.py --check && python validate_artifacts.py
```

### 校验通过意味着什么、不意味着什么

把这件事说清楚很重要，因为一个**永远不可能失败的绿灯比没有灯更糟**。校验器能确立的是：

- 一条**注册声明**等于某个 JSON 路径上的某个具名数值。这是唯一真正有牙齿的检查，它在数字变化时
  会失败，**也在句子被改写、锚点消失时失败** —— 后者正是以前让一整张过期表格活下来的漏洞；
- 每个结果文件都声明了自己的加权方式；
- 日志里没有任何数字是某个 JSON 值的"擦边命中"（这是誊抄过期的典型特征），表格单元格从三位小数
  起必须匹配本节自己的 artifact；
- 没有残留的违禁措辞 —— 被取代的配置（Sobol 之前的抽样数、草稿的预热长度）、指错推断规则的标签、
  以及过度声明（比如把单次运行的 SD–CRLB 吻合说成频率学派意义上的有效性，或者说预热已完全收敛）；
- 环境和冻结的 `.inp` 与产生该缓存时一致。

它**不能**确立：artifact 本身是对的；某个**未注册**的散文数字有确切来源；任意两节之间是否自洽。
语义一致性 —— 缺失的限定语、两节得出相反结论、正确的数字配上错误的描述 —— 在这里无法机器检查，
只能靠人读。图的新鲜度只是文件时间戳比较，**不检查图上画的是不是图注说的那件事**。

描述被取代运行的数字免于数值检查，但句子里必须说明（"早先的一次运行…"、"草稿早先的…"）。

### 运行顺序

在 `Net3/` 目录下、激活环境后运行（不写死解释器绝对路径，所以在任何机器上都能用）。以下是开发机
上的大致耗时，其中一次 168 h 的 EPANET 水质模拟约 35 ms：

```
conda activate water-supply
cd Net3
export MPLCONFIGDIR=../.mplcache
python step0_warmup_convergence.py      # 预热收敛性检验（决定 WARMUP_H）
python step1_freeze_baseline.py         # ~280 s（8192 次 EPANET，全节点）—— 建缓存
python step3_threshold_sensitivity.py   # 瞬时（只用缓存）
python step4_displaced_prior.py         # ~350 s（8192 次 EPANET，仅监测点）
python step4b_sensitivity_curves.py     # 单参数 RMSE 曲线（重新模拟一次扫描）
python step4d_displaced_robust.py       # 首次 ~620 s，之后瞬时（预测库已缓存）
python step5_structural_error.py        # 重新模拟非均质真值；候选复用
python step5c_jitter_sweep.py           # 抖动扫描 + 25 场集合（每场一次真值模拟）
python step5d_structured.py             # 与管长相关的真值 + 相关强度剂量响应
python step6_noise_sensitivity.py       # ~20 s（只用缓存）
python step7_fisher.py                  # ~5 s（约 80 次 EPANET）
python step7_verify.py                  # Jacobian 合理性检查；只打印，不写文件
python step7b_profile.py                # 有缓存的 21³ 网格时 ~250 s；需重建则约 15 分钟
python step7c_ar1.py                    # AR(1) Fisher/CRLB（复用 Jacobian）
python step7c_profile_ar1.py            # AR(1) 剖面；键不匹配时重建 21³ 残差网格
python step8_sensor_bias.py             # ~20 s（只用缓存）
python step8b_kb_sensitivity.py         # 首次 ~620 s，之后瞬时
python step8c_bias_bynode.py            # ~100 s（只用缓存）
python step8d_sensor_drift.py           # ~12 分钟（只用缓存；25 组 × 30 次实现）
python step9_zeroclip.py                # 截尾 vs 朴素零值对比（只用缓存）
python step10_risk_metrics.py           # ~6 s（外加报告步长敏感性运行）
python step11_loo.py                    # ~70 s
python step12_scenarios.py              # ~9 分钟
python step13_known_answer.py           # 解析已知答案检验
python step14_repeated_noise.py         # ~10 s（只用缓存，100 次噪声实现）
python step15_unit_equivalence.py       # ~90 s（3 × 256 次 EPANET；不用缓存）
python step15b_full_regression.py       # 全库 + artifact + 日志回归；会重跑
                                        # 8192 次 legacy 运行并读取两个 git 提交
python provenance.py                    # 刷新 baseline_cache/cache_manifest.json
python validate_artifacts.py            # 用 artifact 交叉核对文档
```

本目录下每一个 `step*.py` 都必须出现在上面；`validate_artifacts.py` 会在漏掉时报错，所以新增一个
step 就必须同时让它可复现。耗时是指示性的，在开发机上测得；只有标了具体数字的才是真的计过时。

### 发布版的溯源

`provenance.py` 会记录 git 提交号以及运行时工作树是否 dirty。因此**在提交之前**运行它，永远会记下
`dirty: true` —— 此时清单描述的是一个已经不存在的工作树。如果这个状态是要被引用的，就先提交，再在
干净的树上运行 `provenance.py`，然后单独提交清单：

```
git commit -am "…"                                   # 代码、artifact 和文档
cd Net3 && python provenance.py                      # 此时记录 dirty: false
git add baseline_cache/cache_manifest.json && git commit -m "chore(net3): record clean provenance"
```

这样清单指向的那个提交，其代码和 artifact 正是产生这些结果的版本；清单自己的提交比它晚一个，这是
不可避免的，**不算不一致**。

有两个 step 脚本不能**在同一目录下**同时运行：WNTR 把 EPANET 的临时文件写成工作目录下的
`temp.inp|rpt|bin`，并发运行会互相覆盖。但它们*可以*在不同工作目录下并行，因为 step 脚本读写的
每一个路径都是绝对路径 —— `cd` 到一个临时目录，用全路径调用脚本即可。

`baseline_cache/baseline.npz`（8192 抽样 × 49 h × 92 节点，约 124 MB）和各个 `*.npy` 预测库都被
git 忽略；需要时用写它们的那个 step 重建。小的 `*.json` 汇总、`cache_manifest.json` 和本日志纳入
版本控制。

## Step 0 —— 预热需要多长？（判据事先声明的收敛性检验）

草稿丢掉前 24 h、评估 24–72 h，但这个数值从未被论证过：水箱初始假设为 0.5 mg/L，风险最高的几个
节点在评估窗口内平均水龄是 30–70 h（Step 10），而 Step 12 的配对检验显示，从草稿的时域换到当前
时域，连续型严重度指标移动了 **+8.6% 到 +13.0%**。本节用**在看到数字之前就固定下来的判据**回答这个
问题 —— 结论是**本模型能提供的任何预热长度都无法同时满足全部判据**，这也是为什么答案是一个可辩护
的折中，而不是一个收敛结果。

### "预热好了"在这里指什么

Net3 的需求模式是 24 个 1 小时的点，10 号泵按 24 h 时刻表运行，所以目标状态不是恒定的稳态，而是
**周期平稳**：一个昼夜周期内的场在下一个周期里重现。每组参数在整个时域上跑一次，然后对相邻 24 h
周期求差。

**公式**：

```
Δ(k) = max over (t in cycle k, node n) | X(t + 24, n) − X(t, n) |
```

**性质**：

- 单位跟随 `X`（氯用 mg/L，水龄用 h，水箱液位用 m）。
- `Δ(k) → 0` 表示从第 `24k` 小时起场是周期平稳的，因此 `24k` 的预热是足够的。
- 对真值和先验盒子的两个角点都计算；**弱角点是决定性的**，因为反应最弱的网络遗忘初始条件最慢。

### 硬性时域上限 —— 这限定了能声称什么

10 号泵由**绝对时刻**控制驱动（`IF SYSTEM TIME IS 01:00:00`、`25:00:00`、…），只枚举到 **159 h**，
而模型时长是 168 h。超过 168 h 后泵会永久关闭，那就是**另一个系统**，不是更长的预热。因此本检验
只有 7 个周期，**无法认证任何超过 144 h 的预热**。Step 12 的"长"设置（168 h / 120 h）本来就正好
卡在这个天花板上。

### 三个结论，按重要性排列

1. **水力几乎立刻稳定，化学不然。** 水箱液位三个周期后已周期性到 0.0001 m，所以驱动端不是问题。
   氯的差值大致每周期按 2 倍几何衰减，在 **120 h** 预热时首次同时满足三个浓度容差 —— 是基线值的
   五倍。
2. **积分风险严重度到时域末端仍未收敛。** 真值的全网平均累积亏缺依次为
   1.005（启动段）→ 0.1348 → 0.0821 → 0.092 → 0.1029 → 0.1092 mg/L·h：在启动瞬变后先降，然后
   **单调上升**。很小的浓度差仍会推动这个积分，因为亏缺积分的是一次阈值穿越。相对变化每周期减半，
   大约在第 6 个周期、即 144–168 h 预热时达到 2% 判据 —— 但模型时域给不出那个周期，所以它只能停留
   在外推。这与 Step 12 配对检验测到的 +8.6% 到 +13.0% 是同一个效应，现在原因也找到了：
   **24 h 窗口坐在瞬变的下降段上，不在平台上。**
3. **水龄依赖时域，在本模型里根本无法收敛。** p95 **水龄**在可得的最后两个周期间仍变化 **12.8 h**，
   每周期只衰减约 12%；外推的穿越点在 600 h 附近，远超 168 h 天花板。所以 Step 10 里的 `mean_age_h`
   是**所选窗口的属性，不是平衡态水龄**。水龄佐证只能表述为固定窗口内的秩关联，绝对水龄不得作为
   稳态值报告。Step 10 同时存了三种窗口定义（`mean_age_h`、`mean_age_last24_h`、`age_final_h`），
   让这个选择显式化。

### 由此确定的流程配置

**120 h** 预热配上现有的 48 h 评估窗口，总长 168 h —— *正好*是模型时域，一点余量都没有。方便的是
残差个数不变：`6 监测点 × 49 小时 = 294`，因为 `168 − 120 = 72 − 24 = 48`，所以非正式对照组的阈值
`0.107` 以及一切由 `N = 294` 推出的量都原封不动地沿用。

### 能写什么、不能写什么

六个判据里三个在 120 h 满足、两个不满足，所以诚实的表述必须两头都设界：

- **可以说：** *"选择 120 h 预热，是因为氯浓度场在该点首次同时在监测点、全网和水箱三处满足事先
  声明的周期平稳容差。这是一个有限时域下的选择：在 120 h 预热下，积分亏缺的周期间残余漂移仍有
  5.1%，水龄在模型 168 h 天花板内的最后两个周期间仍差 12.8 h。"*
- **不能说：** 模型在 120 h 后已完全周期平稳；或者水龄已稳定到与时域无关的平衡值。两者都不成立，
  而且第二条在泵控天花板允许的任何预热长度下都做不到。

### 有两条路可走，这里刻意选了便宜的那条

更强的做法是：用程序把 10 号泵的绝对时刻控制延长到 15–25 个昼夜周期，验证延长后的模型在前 168 h
内逐位复现原模型，然后再跑到严重度和水龄判据收敛。如果预热本身是研究问题，那就该这么做。但这里
它不是：它是一个讨厌的多余参数，而浓度场 —— 本日志中所有似然都建立在它之上 —— 在 120 h 已达容差
内的周期平稳，而且改变预热会让所有已缓存的结果作废。因此 5.1% 的亏缺漂移是作为**严重度指标上的
一条声明限制**被带着走的（Step 10 和 Step 12），而不是被消除掉。

## Step 1 —— 冻结的基线

配置：监测点 `107/113/15/145/209/231`；入口 1.0，水箱 0.5；**168 h 模拟，120 h 预热**（Step 0），
1 h 报告步长，5 min 水质步长；`k_b = -0.5`；真值
`(k_w,old, k_w,avg, k_w,new) = (-1.0, -0.1, -0.05) m/day`；噪声种子 42，Sobol 扰动种子 0；
**8192 = 2¹³ 个扰动 Sobol 先验抽样**。评估窗口 48 h，故 `N = 6 × 49 = 294` 个残差，未变。

这已经不是对草稿的复现。有三处选择是刻意改动的，理由记录在此而非沿袭：

| 选择 | 草稿 | 现在 | 为什么 |
| --- | --- | --- | --- |
| 预热 | 24 h | 120 h | Step 0：在此之前氯并非周期平稳 |
| 抽样 | 伪随机，2¹¹ 量级 | 8192 扰动 Sobol | 在草稿的样本量下，正式似然的有效样本量只有约 37 |
| 加权 | 单一非正式评分 | 三种方案并列 | 非正式评分不是似然；见下 |

### 三种加权方案，同样的数据，同样的抽样

正式截尾高斯似然是主分析；正式 iid 用来分离"把传感器下限的零当作精确测量"的代价；非正式 GLUE
评分作为对照保留。

**公式**（每个候选，差一个可加常数）：

```
正式 iid       ℓ = −(1/2) Σ_j,t ((y_jt − μ_jt)/σ)²
正式截尾       ℓ = −(1/2) Σ_{y>0} ((y_jt − μ_jt)/σ)²  +  Σ_{y=0} log Φ(−μ_jt/σ)
非正式 GLUE    ℓ = −(1/2) (RMSE/σ)²                    · 1[RMSE < 阈值]
```

**性质**：

- 非正式评分是正式 iid 评分**除以** `N = 294`。等价地，它是一个 `σ_eff = σ√N = 0.1 × 17.15 = 1.71 mg/L`
  的高斯似然 —— 是传感器噪声的 17 倍，比 1.0 mg/L 的入口浓度还大。这就是为什么它在行为集合内部
  几乎是平的。
- 正式方案**不带阈值**；硬性截断属于 GLUE 对照组，不属于似然。
- 窗口内 294 个点中有 10 个被传感器下限截断（全记录 1014 个点中有 43 个），所以截尾方案和 iid
  方案并不等同。

| 方案 | ESS | 熵（bit，满值 13.00） | `k_w,old` | `k_w,avg` | `k_w,new` |
| --- | --- | --- | --- | --- | --- |
| 正式截尾（主） | 157 | 7.97 | -0.9876 ± 0.0938 (25.0%) | -0.1091 ± 0.0142 (30.7%) | -0.0440 ± 0.0078 (28.3%) |
| 正式 iid | 154 | 7.94 | -0.9708 ± 0.0920 (24.5%) | -0.1087 ± 0.0141 (30.6%) | -0.0441 ± 0.0078 (28.3%) |
| 非正式 GLUE，阈值 0.107 | 4783 | 12.22 | -1.0115 ± 0.2668 (71.1%) | -0.1170 ± 0.0424 (91.8%) | -0.0492 ± 0.0242 (88.2%) |
| 非正式 GLUE，阈值 0.120（草稿） | 7062 | 12.79 | -0.9431 ± 0.3220 (85.8%) | -0.1196 ± 0.0455 (98.4%) | -0.0529 ± 0.0269 (98.0%) |

括号里是先验宽度保留比（= 后验 SD / 先验 SD）。草稿的配置对 old / average / new 分别保留了
**85.8 / 98.4 / 98.0%** 的先验宽度；在**完全相同的观测**上，正式截尾只保留 25.0 / 30.7 / 28.3%。
数据本身没有任何变化 —— 变的只是加权方式从中提取了多少信息。**这一个对比是本日志中最重要的结果**，
后面每一节要么是它的推论，要么是在检验它在真实误差下还能撑多远。

### 抽样收敛性

扰动 Sobol 集合的前 `2^k` 个子集本身就是平衡设计，所以下面四行是精确的子设计，而不是临时抽稀：

| 抽样数 | ESS | `k_w,old` 中位数 | `k_w,avg` 中位数 | `k_w,new` 中位数 | 中位数最大漂移 |
| --- | --- | --- | --- | --- | --- |
| 1024 | 18.8 | -0.9744 | -0.1096 | -0.0444 | — |
| 2048 | 39.3 | -0.9752 | -0.1097 | -0.0435 | 0.033 先验 SD |
| 4096 | 78.0 | -0.9787 | -0.1094 | -0.0437 | 0.009 先验 SD |
| 8192 | 156.7 | -0.9787 | -0.1090 | -0.0437 | 0.010 先验 SD |

ESS 与抽样数成正比（始终是其 1.9%），所以先验抽样**无法靠蛮力变得高效** —— 但**分位数已经收敛**：
最后两个规模之间中位数只移动 0.01 个先验 SD，5/95 端点移动更小。ESS 在这里是保守的诊断量；真正
买到稳定性的是 Sobol 设计的空间填充性。

候选最小 RMSE 为 0.0971 mg/L，对照的是**同一 120–168 h 标定窗口上实现的噪声 RMSE 0.0973 mg/L**
—— 这个比较必须窗口对窗口，全记录实现噪声 RMSE（0.0960，`noise_rmse_full_record`）是**另一个样本**，
不得在此引用。对照组的行为集合计数：阈值 0.107 时 4786/8192，阈值 0.120 时 7084/8192。

缓存 `baseline.npz` 保存了全部 8192 个候选预测 `C_all (8192 × 49 × 92)` 以及两个正式对数似然，
所以后续每一步都能**不重跑 EPANET**地重新计算权重。

## Step 2 —— 先验 vs 行为可辨识性（纠正一处过度声明）

均匀区间 `[a, b]` 的先验 SD：

```
prior_SD = (b − a) / √12
```

| 组 | 先验区间 | 先验中点 | 先验 SD | 真值 | 非正式 均值 ± SD（保留比） | 正式 均值 ± SD（保留比） |
| --- | --- | --- | --- | --- | --- | --- |
| old | [-1.5, -0.2] | -0.850 | 0.375 | -1.00 | -0.9431 ± 0.3220 (85.8%) | -0.9876 ± 0.0938 (25.0%) |
| average | [-0.2, -0.04] | -0.120 | 0.046 | -0.10 | -0.1196 ± 0.0455 (98.4%) | -0.1091 ± 0.0142 (30.7%) |
| new | [-0.10, -0.005] | -0.0525 | 0.027 | -0.05 | -0.1196 → 见注 | -0.0440 ± 0.0078 (28.3%) |

非正式那一列用的是草稿的阈值 0.120，以便复现产生该过度声明的那个配置；其中 `k_w,new` 是
-0.0529 ± 0.0269（保留 98.0%）。

解释必须按方案分开写，因为两者分歧的是**结论**，不只是数位：

- **在非正式 GLUE 评分下，原来的批评成立。** 三个分布都保留了 86–98% 的先验宽度，加权均值贴在
  先验中点附近。它们表面上与真值吻合，是因为**先验区间本来就是围绕这些真值设的**，不是数据的功劳。
- **在正式似然下则不成立。** 同样的观测把三个系数都收缩到先验宽度的 25–31%。所以"数据无法辨识
  average 和 new"从来就不是关于数据的陈述，而是关于**用来给数据加权的那个评分**的陈述。

删除的过度声明（原在 §4.4）：*"每一组的加权均值都接近其真值。"* 替换后的说法必须点明推断约定：
在非正式 GLUE 评分下，各均值由先验主导；在正式似然下，三者都被数据告知，但在这一次噪声实现上
仍有最多约 0.7 个后验 SD 的偏差。

## Step 3 —— 行为阈值敏感性（不重跑 EPANET）

RMSE 统计量在真值处的抽样 SD：

```
sd(RMSE) ≈ σ / √(2N) = 0.10 / √(2·294) = 0.0041 mg/L      (N = 6 监测点 × 49 h = 294)
```

观测到的候选最小 RMSE = 0.0971 mg/L，对照同一 120–168 h 标定窗口上实现的噪声 RMSE **0.0973 mg/L**。
（全记录实现噪声 RMSE 是 0.0960；它描述的是整个观测集，**不是**窗口 RMSE 的对照量。）

### 文献里有三个不同的量都被叫做"噪声底"，所以本日志给它们各自命名

`σ = 0.10 mg/L` 是生成观测时用的**名义**噪声水平；`0.0973` 是标定窗口上**实现的**噪声 RMSE；
`0.0960` 是全记录上实现的噪声 RMSE。下表按 `σ` 缩放，不按任何一个实现值。

### 本节的适用范围，重申一次

行为阈值**只属于非正式 GLUE 对照组** —— 正式似然不带任何**接受阈值**。所以这是一次**对照组本身**的
敏感性分析，从中该得出的结论是"对照组的答案有多依赖分析者的选择"，而不是"数据说了多少"。

> **中文版注（术语避坑）**：这里的"阈值"与"正式**截尾**似然"里的"截尾"是**两件不同的事**，中文里都
> 容易被叫成"截断"。**接受阈值**作用在**候选参数**上（`1[RMSE < T]` 把超阈值的候选权重直接置零）；
> **截尾**作用在**观测数据**上（落在传感器下限的读数按 `Y* ≤ 0` 计入似然，而不是按精确的 0）。两个
> 正式方案下 `n_nonzero = 8192`，即 8192 个候选**一个都没有被排除**；非正式 GLUE 在阈值 0.107 下
> `n_nonzero = 4786`，在 0.120 下是 7084。此外 Step 12 还有第三种"截断"——`1e-6` 权重下限的**数值
> 截断**（保留 2196/8192），日志明确声明它**不是**行为阈值，并量化了代价（丢弃权重合计 3.79 × 10⁻⁶）。

| *正式截尾（无阈值）* | *-0.9876 ± 0.0938 (25.0%)* | *-0.1091 ± 0.0142 (30.7%)* | *-0.0440 ± 0.0078 (28.3%)* |

阈值收紧时（0.120 → 0.107）：

- **old 略有锐化**：SD 从 0.3220 → 0.2668（保留比 85.8% → 71.1%），均值向真值移动
  （-0.9431 → -1.0115，真值 -1.0）。
- **average / new 几乎不动**：SD 保留比维持在 88–98%，均值仍在先验中点附近。
- **但没有任何被测阈值能接近正式结果** —— 原因是**结构性的**，不是所试具体数值的性质。硬性截断是
  给评分乘上一个示性函数，它**无法恢复非正式评分丢掉的因子 `N`**，所以任何截断都不会把它变成高斯
  似然。扫描在经验上表明的是：在能保持可用接受率的范围内，从 0.120 收紧到 0.107 对 `old` 大约挽回
  了差距的七分之一，对 `avg`/`new` 几乎没有；而**换成正式似然则把每一个 SD 都砍掉三分之二**。早先
  的读法 —— "average/new 无法被任何阈值锐化，所以它们的不可辨识性是监测阵列的性质" —— 是**错的**：
  那是**评分**的性质。监测阵列确实为它们提供了信息，正式那一行和 Step 7 的 CRLB 都证明了这点。

风险前 6 名节点在各阈值下是**稳定的**：`131 > 129 > 141 > 127`，然后 `15`/`139` 在 0.107 与另外两个
较松阈值之间互换位置（非零风险节点数固定为 24）。因此领先集合的**身份对阈值不敏感**，只有第五、
第六名的顺序会动，而这两者的间距小于各自的集合离散度。

结论：

- 草稿的 0.12 阈值高出**名义**噪声水平 `σ = 0.10` 达 4.85 个 sd(RMSE)
  （`sd_above_floor = (thr − σ) / sd(RMSE)`），所以处在真值上的参数组几乎必然通过 —— 这个过滤器
  只能拒掉**错得离谱**的参数组。
- 收紧到一个可辩护的约 95% 带（0.107）会锐化 **old**，而把 **average/new** 留在先验附近。
  **这是评分的局限，不是监测阵列的局限。** 本日志的早先版本从同一张表得出了相反的结论，那是草稿
  中**最严重的一处错误**：它把加权规则的低效说成了传感器网络的性质。上表中的正式那一行、Case-A
  CRLB（Step 7）和连续剖面区间（Step 7b）都表明，监测阵列确实为 average 和 new 提供了信息。
- 运行层面的风险排序对阈值选择是稳健的，这是一个真正有用的发现，且不受上述纠正影响。

## Step 4 —— 位移先验实验（初步，单次噪声实现）

真值、监测阵列、基线观测都不变；**只移动先验**。每个区间宽度不变，但中点设为 `真值 − 1 先验 SD`。
位移方向朝下（衰减更强），因为朝上会让上界变正；所有位移后的区间都保持非正，且仍然包含真值
（此时真值位于位移中点上方一个先验 SD 处）。

问题：观测能不能把行为均值拉回真值？

行为集合 3359/8192（41.0%），最小 RMSE 0.0972。加权方式：非正式 GLUE，与草稿一致。

| 组 | 原中点 | 位移后区间（中点） | 真值 | 行为均值 ± SD | SD 保留比 | 缩小的差距 |
| --- | --- | --- | --- | --- | --- | --- |
| old | -0.850 | [-2.025, -0.725] (-1.375) | -1.00 | -1.2185 ± 0.3287 | 87.6% | 42% |
| average | -0.120 | [-0.226, -0.066] (-0.146) | -0.10 | -0.1272 ± 0.0407 | 88.1% | 41% |
| new | -0.0525 | [-0.125, -0.030] (-0.077) | -0.05 | -0.0556 ± 0.0175 | 63.9% | 80% |

（"缩小的差距"= 行为均值从位移中点朝真值移动的距离，占那 1 个先验 SD 差距的比例。）

解读：

- 观测把位移后的均值**大幅**拉回真值 —— 分别为 42%、41% 和 80% —— 并且接受率降到 41%，说明目标
  函数在这里是有区分力的。
- **这与草稿早先的运行结果相反。** 在 24 h 预热下，同一实验只缩小了 9%、12% 和 22% 的差距，且保留
  了 99.8% / 96.9% / 92.8% 的先验宽度 —— "连被告知的那个系数都恢复不了"这一读法正是建立在此之上。
  在修正后的预热下，数据的信息量远比那个读法所假设的要大。
- **归因尚未确定。** 两次运行之间同时变了两件事：预热（24 h → 120 h）和抽样设计（Sobol 之前被取代
  的抽样 → 8192 Sobol）。能把两者分开的是 Step 0 用的那种配对窗口设计 —— 一次长模拟、两个窗口、
  共享噪声和共享抽样 —— 而这个实验还没有这么跑过。在跑之前，诚实的说法是"位移先验的结论对预热
  敏感"，而不是"预热造成了全部差异"。
- `k_w,old` 的单边可辨识性声明因此也需要重新检验；它是从那个 9% 推出来的。应当承担这个论断的证据
  是 Step 4b 的目标函数曲线和 Step 4d 的 30 次实现版本，**不是**本表。

状态：这张单次实现的表是初探。稳健版本（30 次噪声实现 × 两个阈值，外加一个 old 朝更弱方向的位移）
是下面的 **Step 4d**，报告时以它为准。

## Step 4b —— 单参数目标函数曲线（为什么 old 是单边的、avg/new 是平的）

每个系数在其先验范围内（并略微越界）扫描，另外两个固定在真值；RMSE 相对基线含噪观测计算
（`step4b_sensitivity_curves.py`）。标定窗口上实现的噪声 RMSE（三者都在真值）= **0.0973 mg/L**
（`noise_floor_rmse`）；扫描中的最小值是 0.0972 mg/L。这里**不施加任何加权** —— 画出来的对象就是
目标函数本身，两条阈值线只是用来显示非正式对照组会在哪里切一刀。

单参数目标函数：old 是不对称的谷，avg/new 是平的

| 系数 | 在其先验范围内的 RMSE 变幅 | 以 sd(RMSE) 为单位 | 解读 |
| --- | --- | --- | --- |
| old | 0.0412 mg/L (0.0972 → 0.1384) | 10.0 | 弱侧陡峭（弱端超过 0.12 阈值 → 可被拒绝）；强侧平坦 |
| avg | 0.0075 mg/L (0.0973 → 0.1048) | 1.8 | 整个先验都低于对照组阈值 → 各取值*对该规则而言*不可区分 |
| new | 0.0092 mg/L (0.0972 → 0.1064) | 2.2 | 整个先验都低于对照组阈值 → 各取值*对该规则而言*不可区分 |

- **old 是一个不对称的谷**：目标函数只在弱侧爬升到行为阈值以上，所以数据能**拒绝弱的 old，却无法
  在强的取值之间区分**（从约 -0.9 到 -2.2 m/day 是平底）。这就是单边可辨识性的机制，也调和了
  Steps 2–3 与 Step 4：old 在基线先验（跨在陡壁上）下收缩，但在位移到强区的先验（落在平底上）下
  不收缩。
- **avg / new**：在整个先验范围内扫描它们，目标函数变化 < 0.01 mg/L，且始终低于 0.107/0.12 阈值，
  所以每个取值都能通过对照组的过滤。**但这个变幅是 1.8–2.2 × sd(RMSE)**，也就是说它**并不在噪声
  之内**：一个使用全部 `N = 294` 个残差（而不是它们的均方根）的规则是能看见它的 —— 正式似然干的
  正是这件事，这也是它把 avg/new 收缩到先验约 30% 的原因。因此正确的读法是"监测点对 avg/new **弱**
  但**真实**地敏感，而一个基于 RMSE 的阈值把这份敏感性丢掉了"，**不是**"监测点对它们不敏感"。

## Step 4d —— 稳健版位移先验（30 次噪声实现 × 两个阈值）

两种位移设计（`step4d_displaced_robust.py`），**每种都同时位移三个系数**（宽度固定，真值保持在
区间内），所以每一个"缩小差距"的数值都有意义。两种设计只在 old 的方向上不同：

- **DOWN**：old / avg / new 的中点都设为 `真值 − 1 先验 SD`（强衰减一侧）。
- **OLDUP**：old 朝弱/陡的一侧位移，名义上到 `真值 + 1 先验 SD`，但上界被截到 -0.005 以保持非正。
  **这个截断在这里起作用了，而且影响大到不能忽略**：窗口不得不整体下移 **0.0303 m/day**，得到的
  OLDUP old 先验是 `[-1.305, -0.005]`。它的中点因此位于真值上方约 **0.92** 个先验 SD，而不是设计
  意图的 1.0，所以实际测试的位移比设计名义值略小。这个平移被记录在 artifact 里
  （`upper_cap_shift_applied`），使得实际设计可以据此还原 —— **一个会改动设计却不留痕迹的保护措施
  是不可审计的**。

每种设计：8192 个扰动 Sobol 前向运行缓存一次（以设计盒子为键，所以改动一个设计只会让它自己的库
失效），然后在 30 组独立含噪观测上重新计算缩差统计量。报告形式为跨噪声的**中位数 [四分位距]**。
`gap closed`（缩小的差距）= 后验均值覆盖的"位移中点 → 真值"距离的比例（0% = 停在先验中点，
100% = 到达真值）。

**主分析 —— 正式截尾似然，无阈值**（ESS 中位数：DOWN 152 / OLDUP 147）：

| 系数 | DOWN（old 朝强侧位移） | OLDUP（old 朝弱侧位移） |
| --- | --- | --- |
| old | **88% [67–104]**（SD 保留 27%） | **112% [95–132]**（SD 保留 25%） |
| avg | **95% [75–110]**（SD 保留 29%） | 95% [75–111]（SD 保留 29%） |
| new | **96% [80–122]**（SD 保留 28%） | 96% [80–122]（SD 保留 29%） |

**对照 —— 非正式 GLUE**，分别在草稿阈值 0.12（保留率 DOWN 87% / OLDUP 64%）和可辩护的约 95% 带
0.107（保留率 41% / 30%）下：

| 系数 | 0.12, DOWN | 0.12, OLDUP | 0.107, DOWN | 0.107, OLDUP |
| --- | --- | --- | --- | --- |
| old | 9% [5–13] (99%) | 61% [54–64] (68%) | 28% [14–55] (92%) | 85% [75–94] (52%) |
| avg | 14% [10–19] (97%) | 15% [10–20] (97%) | 43% [27–58] (87%) | 43% [29–60] (88%) |
| new | 23% [14–32] (92%) | 14% [9–21] (95%) | 78% [56–82] (65%) | 66% [42–71] (69%) |

结论，而且不是本节上一版所报告的那些：

1. **在主规则下，三个系数从任一方向都基本被完全拉回。** 中位数在 88–112% 之间，四分位距都横跨
   100%，而且每一格的后验宽度都塌缩到先验的 25–29%。位移先验是检验先验主导性的最干净的方法，而
   正式似然对 average 和 new 的通过程度与对 old 一样彻底。
2. **对照组复现了草稿的"可辨识性梯度"，而那个梯度是对照组的产物。** 在 0.12 下，非正式评分对三个
   系数中的两个只挽回 9–23% 的差距，对处在陡侧的 old 挽回 61%；收紧到 0.107 则把所有数值都抬高。
   把四列对照读下来，表面上的排序 `old ≫ new > avg` 及其表面上的阈值依赖性，在换掉评分之后**双双
   消失**。旧读法中留存下来的只有一条：**对照组**的答案严重依赖分析者选的阈值。
3. **old 的不对称是真的，但远比看上去弱。** 即便在主规则下，old 从强侧恢复得（88%）也略少于从弱侧
   （112%），这是 Step 4b 中那个不对称谷的残留痕迹：目标函数对 old 能有**多弱**的约束，比对它能有
   **多强**的约束更锐利。而在非正式评分下，同样的不对称是 9% 对 61% 的**鸿沟**。所以单边可辨识性
   这个论断应当表述为**正式后验的一种轻微方向依赖性**，而不是单边可辨识性。
4. **保留比那一列是诊断量，不是结果。** 主规则的有效样本量在两种设计下都约为库容量的 2%。这足以
   支撑此处引用的中位数和四分位距（Step 1 表明分位数从 4096 抽样起就稳定了），但也正是本节不引用
   任何更精细统计量的原因。

**可辨识性梯度 —— 修订版。** 这些受控实验**不再支持**把 `old ≫ new > avg` 当作关于数据的陈述。在
正式似然下，三个系数被告知到**相对精度**相当的程度（SD 保留 25 / 31 / 28%，Step 1），而且三者都能
从位移先验中恢复。它们之间真正的差别不是数据说不说话，而是一旦允许现实中的混杂因素进入，这些信息
有多**脆弱** —— 那是 Step 7（Case C）、8b 和 8c 的主题。因此应当报告的句子是关于**实用稳健性**上的
梯度，而不是可辨识性本身的梯度。

### Step 5c —— 非均质性幅度扫描（0 控制组 / ±20 / 35 / 50%）

设计相同，抖动幅度加大（`step5c_jitter_sweep.py`；均质候选的预测与真值无关，所以 8192 个缓存候选
可直接复用，只需重新模拟真值）。偏差 = 加权均值 − 各分区真实算术均值。

**这里需要两处纠正，而且它们的方向相反。** 扫描现在包含了一个 `jitter = 0` 的控制组，并在两种加权

*减去控制组。* 在 `jitter = 0` 时真值恰好是均质的，所以在那里测到的任何东西都不可能是结构性的 ——
出现的任何偏差都是那次实现的噪声。因此原始偏差那一列**高估**了结构效应；`incr`（相对控制组的增量）

*使用正式加权。* 非正式评分在行为集合内部几乎是平的，所以它的加权均值被钉在接受盒子的中心附近，

偏差随分区内抖动的变化，以均质控制组为基准

**上面这张单场表显示了什么，以及为什么它不是结论。** 表面上看，正式那一列说对称非均质性会让
old 分区的系数产生偏差，增量单调增长到 ±50% 时的 −0.049 m/day（0.36 个后验 SD），而非正式评分对
同一增量给出的是 −0.013（0.10 SD）。非正式与正式的这个对比是真实的，也就是别处反复出现的那种"惯性"。
但每一行都只用了**一个**抖动场（种子 12345），所以增量里混杂了非均质性的效应和某一个空间排布的
偶然性。在做出任何声明之前，必须先把两者分开。

### Step 5c-ensemble —— ±20% 下的 25 个独立非均质场

候选预测与真值无关，所以在多个场上重复只需每场一次真值模拟。25 个场，正式加权，已减去控制组：

| 分区 | 偏差均值 | 偏差 SD | 结构增量均值 | 增量 SD | \|均值\| / SD |
| --- | --- | --- | --- | --- | --- |
| old | +0.0231 | 0.0335 | **+0.0107** | 0.0335 | **0.32** |
| average | −0.0089 | 0.0046 | +0.0002 | 0.0046 | 0.04 |
| new | +0.0055 | 0.0021 | −0.0005 | 0.0021 | 0.24 |

**这把单场的读法推翻了，连符号一起。** `old` 的集合平均结构增量是 **+0.0107** m/day —— **更弱**的
衰减 —— 而单场给出的是 **−0.0325**，**更强**的衰减。场间散布是 0.0335，是均值的三倍，三个分区的
`|均值| / SD` 分别是 0.32、0.04 和 0.24。所以在 ±20% 的对称分区内非均质性下，**不存在任何高于场间
变异性、可被检出的系统性结构偏差**，而单场那个数字与场的选择无法分离。

因此应当带走的结论仍是最初那个：在本网络、本噪声水平下，**对称的、零均值的分区内非均质性会被平均
掉**。沿途那些纠正所确立的事实依然成立、依然重要 —— 必须减去控制组、非正式评分确实低估了存在的
效应、结构残差有一个网格底 —— 但这些加起来并不构成一个针对**对称**非均质性的"精确但有偏"效应。
要得到那个效应，非均质性必须是**结构化的**，而不是零均值的 —— 即与某个分组平均无法保留的管段属性
相关。Step 5d 检验了一种这样的结构，用**管长**作为相关属性。

关于本节是怎么得出来的，有一点值得记，因为它关系到论文该如何对待任何单次实现的结果：这里的论断
**已经被推翻过两次**，第一次是加入 `jitter = 0` 控制组并换成正式似然，第二次是把一个场换成 25 个场。
两次推翻都来自**去掉对某一个任意选择的隐藏依赖**，而且**从拟合质量上完全看不出来** —— 拟合从头到尾
都很好。

结构残差从 0.0068 增长到 0.0145 mg/L，但其中只有 0.0013 → 0.0090 是高于网格底的，所以早先"残差是
噪声底的 7%"这个读法**高估了约五倍**；相对于实现的窗口噪声 RMSE 0.0973，±20% 时真正的结构部分是
**1.3%**。风险排序在所有幅度下都不变。

### Step 5d —— 结构化（与管长相关）的分区内非均质性 → 精确但有偏

位置一致的设计：真值保留三个**位置**分区，但每个分区内部 `k_w` **与管长相关**（管越长衰减越强，
因子 `1 + 0.5·s`，`s ∈ [−1,1]` 按分区内长度排名给出）。每个分区的**算术**均值被精确保持在分区均值上，
而**长度加权**均值则被推向更强，于是三分区均质拟合的两个候选目标被分开、可以被区分
（`step5d_structured.py`；候选库复用缓存）。

长度加权是一个**示意性的代理目标**。它*不是*停留时间加权、也不是水力有效系数，两者绝不可等同 ——
见下面的限定说明。

主规则 = 正式截尾似然；非正式对照并列显示。`hom. offset`（均质基线偏移）是同一规则在**均质**基线上
相对真值的偏离，也就是在完全没有结构误差时它会给出什么；**把任何位移读作结构性之前必须先减掉它**。

| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| old | -1.000 | **-1.2404** | -0.2404 | **正式截尾** | **-1.1444 ± 0.1123** | **-0.1444** | +0.0124 | **60%** |
| old | | | | 非正式 GLUE | -1.0666 ± 0.2549 | -0.0666 | -0.0115 | 28% |
| average | -0.100 | -0.1238 | -0.0238 | **正式截尾** | **-0.1349 ± 0.0170** | **-0.0349** | -0.0091 | **147%** |
| average | | | | 非正式 GLUE | -0.1300 ± 0.0416 | -0.0300 | -0.0170 | 126% |

结构化非均质性：拟合朝长度加权值移动

**单次实现的读法（一次噪声抽样）。** 结构残差仍然很小（0.0063，所以拟合依然*精确*：RMSE 0.0968，
刚好低于实现的窗口噪声 RMSE 0.0973），长度加权代理与算术均值明显分离（old −1.2404 对 −1.000），
而在主规则下拟合系数沿该方向偏离算术均值，幅度分别是"算术 → 代理"差距的 60%（old）、147%
（average，即越过了代理值）和 45%（new）。与对照那一列的比较有两点值得注意：old 的正式位移
**是它的两倍多**（−0.1444 对 −0.0666），所以非正式评分低估结构效应的方式，与它低估传感器偏置
（Step 8）的方式一样。而正式规则的均质基线偏移很小（+0.012 / −0.009 / +0.006），这正是结构归因
在此成立的前提：在非正式评分下，每个"结构"位移中都有相当一部分其实是评分自身的偏移。

这些仍然只是一次噪声抽样。下面的剂量响应才是把抽样平均掉之后这个效应的样子。

### Step 5d-dose —— 相关强度 × 30 次噪声实现

与 Step 5c 不同，这里的真值是确定性的（按长度排名），所以没有非均质场可平均；单次实现的风险来自
噪声抽样。而且如果这个效应是真的，它必须在 `CORR = 0` 处**消失**（此时两个候选目标重合），并随
`CORR` 增长。两者一次检验。统计量是"算术 → 长度加权"差距被走过的比例：0 表示拟合落在算术均值上，
1 表示落在长度加权值上。

**主分析 —— 正式截尾似然：**

| `CORR` | 差距 (old) | old: 中位数 [5, 95] | average | new |
| --- | --- | --- | --- | --- |
| 0.00 | 0.0000 | 控制组 —— 两个目标重合 | 控制组 | 控制组 |
| 0.25 | −0.1202 | +1.10 [−0.29, +2.47] | +1.26 [−0.95, +3.72] | +0.98 [−0.89, +2.66] |
| 0.50 | −0.2404 | +0.86 [+0.12, +1.46] | +1.12 [−0.07, +2.43] | +0.92 [−0.03, +1.78] |
| 0.75 | −0.3606 | +0.74 [+0.23, +1.06] | +1.07 [+0.22, +1.93] | +0.89 [+0.26, +1.46] |

**对照 —— 非正式 GLUE**（只给中位数；同样的运行、同样的差距）：

| `CORR` | old | average | new |
| --- | --- | --- | --- |
| 0.25 | +0.65 | +2.00 | +0.89 |
| 0.50 | +0.43 | +1.22 | +0.78 |
| 0.75 | +0.34 | +0.97 | +0.72 |

**结论，而且比单次抽样所暗示的更强 —— 在主规则下。** 位移比例的中位数在**每一个**相关强度、
**每一个**分区都是 **0.74–1.26**：拟合系数**基本完整地**跟踪长度加权代理，而不是部分跟踪。单次实现
的 60% / 147% / 45% 都落在这些区间内，所以它只是一个中位数接近 1 的量的一次带噪抽样。

**对照组没有复现这一点，而且对 `old` 差了一倍。** 在非正式评分下，old 分区的中位数随 `CORR` 增大
从 +0.65 **降到** +0.34，也就是说，恰恰在正式规则读出"基本跟踪了全部差距"的地方，它读出的是"拟合
只跟踪了差距的三分之一"。**两种规则的比例都随 `CORR` 下降**（正式 +1.10 → +0.86 → +0.74；非正式 +0.65 → +0.43 → +0.34），趋势方向相同而非相反；而且由于差距本身在变大（old 为 0.120 → 0.240 → 0.361 m/day），**两者的绝对位移都在上升**（正式 0.132 → 0.207 → 0.268；非正式 0.078 → 0.104 → 0.123）。对照真正做的是稳定地衰减到正式值的 0.59、0.50、0.46 倍。这与 Steps 3、5c、8 和 8b 中是同一种
惯性：一个在其行为集合内部几乎平坦的评分，无法跟随系统性位移。因此"拟合跟踪长度加权代理"这句话
是一个**正式似然**的陈述，引用时必须如此标明。

这些区间的表现也符合一个真实效应应有的样子。它们随 `CORR` 增大而**收窄** —— 0.25 时的
[−0.29, +2.47] 对 0.75 时的 [+0.23, +1.06] —— 因为分母上的差距在增大而分子上的噪声没有。在
`CORR = 0.75` 时三个区间**都排除了零**，所以在足够的相关强度下这个结论是被解决了的：拟合与"坐在
算术均值上"不相容，而与"跟踪长度加权值"相容。在 `CORR = 0.25` 时它没有被解决 —— 这是本设计能检出
的诚实边界。

注意与 Step 5c 的对比，这也是同时保留两者的意义所在：对称非均质性在 25 个场上没有产生可检出的偏差，
而**同等幅度**的长度**相关**非均质性产生了一个被完全解决的偏差。**是非均质性中的结构、而不是非均质
性本身，破坏了平均效应。** 这里检验的结构是一种合成的*管长*相关性，之所以用它，是因为它能干净地
把两个候选目标分开；它**不是**流径、停留时间或 Jacobian 加权，而且本设计无法说明真实网络会与哪个
属性相关。

**长度加权绝不能称为停留时间加权，这限定了论断的范围。** 一根管的反应权重取决于它的流量、流向、
管径、停留时间，以及六个监测点对它的观测强度。长度只是其中一个代理；它恰好能在本设计中把两个候选
目标分开，这正是本设计有用的原因，但这里没有任何东西表明它就是**正确**的目标。因此有两句强弱不同
的陈述，只有较弱的那句是被支持的：

- **被支持：** 结构化非均质性会让均质估计偏离算术均值，方向朝着长度加权代理，所走过的差距比例其
  中位数接近 1，且在 `CORR = 0.75` 时区间排除零。
- **不被支持：** 均质拟合*恢复了*停留时间加权或有效系数。要确立拟合真正估计的是什么，需要一个
  敏感度加权或 Jacobian 加权的有效均值，本节没有计算它。**那是待做的工作，不是结果。**

**关于幅度的诚实说明。** 在主规则下，old 分区的偏移 −0.1444 是 1.29 个后验 SD（0.1123），所以结构
位移现在**与后验宽度相当**，而不是埋在里面 —— 这是一个比非正式对照给出的 0.26 SD **更强也更值得
警惕**的结果。本节所展示的仍然是那个*机制*：拟合保持精确（RMSE 在噪声底上），而系数却被拉离了场
的简单平均。另外注意，网格拟合在这里是个粗糙的工具：old 分区的网格步长是 0.2170 m/day（半步
0.1085），比被测的位移还大，所以 `grid_fit` **分辨不出它**，只有加权均值能。

### Step 5e —— 网格搜索的"恢复"是围绕答案摆出来的（§3.3 后半）

7×7×7 的网格范围是围绕真值选的，所以每个真值最近的网格节点在构造上就很近：

| 系数 | 网格步长 | 距真值最近的节点 | 距离 | 半步 |
| --- | --- | --- | --- | --- |
| old | 0.217 | -1.067 | 0.067 | 0.108 |
| avg | 0.027 | -0.093 | 0.007 | 0.014 |
| new | 0.016 | -0.052 | 0.002 | 0.008 |

**无噪声**最佳均质拟合 —— `(-1.067, -0.093, -0.052)`，存为 `structural_best_homogeneous` ——
**恰好**就是这些最近节点，所以对一个干净的目标函数而言，"恢复到最近网格节点"是由**网格摆放**保证的，
不是由数据保证的。**带噪的网格拟合则只在 `old` 上一致，在另外两个上并不一致**，这才是更有信息量的
一半（此前被写成"每次运行都返回最近节点三元组"）：Step 5a 记录的是 `(-1.067, -0.120, -0.037)`，
Step 5d 记录的是 `(-1.067, -0.147, -0.052)`。推论：

- 确定性网格**无法区分可辨识与不可辨识的系数**，而且它是以两种相反的方式同时失效的。对 `old`，
  无论数据说什么它都落在最近节点上，所以那里的命中是由摆放保证的。对 avg/new，被拟合的节点反而在
  各次运行间游走一到两个步长（avg 会返回 -0.093、-0.120 或 -0.147，取决于真值场和噪声抽样），因为
  目标函数在它们整个先验范围内几乎是平的（Step 4b），而网格步长比任何能区分它们的量都粗。两种情形
  下网格都会吐出一个**读起来像是被恢复出来的**三元组。这就是为什么草稿的网格看起来像是三个系数都被
  成功恢复，掩盖了 GLUE 揭示的东西。
- 草稿报告的 old 的 10 次实现散布（±0.12 m/day）≈ **半个网格步长**（0.108），即主要是量化误差，
  不是真正的估计不确定性。

对论文的修正：把网格只作为实现层面的合理性检查呈现，可辨识性和不确定性依靠 GLUE（配合 Steps 2/4
的位移先验）。

### Step 5 —— 总体

- **不相关的分区内非均质性（±20–50%，Step 5c）**：分组模型是**稳健的**。后验均值停留在算术均值上，
  误差在场间散布之内，风险排序被保持。在 ±20% 的 25 个独立场上，结构增量是 `+0.0107 ± 0.0335`
  （|均值|/sd = 0.32），即不可检出。
- **长度相关的分区内非均质性（Step 5d）**：**精确但有偏**。拟合停在实现的窗口噪声 RMSE 上，而
  **每一个分区**的系数都朝长度加权代理移动。在 30 次噪声实现上，"算术 → 代理"差距被走过比例的
  中位数在**每个分区、每个 `CORR` 水平**都是 **0.74–1.26**，且 `CORR = 0.75` 时三个区间全部排除零。
  单次实现的 60% / 147% / 45% **不得**当作结论引用，也**不得**用来给分区排序：它只是一次抽样，
  而 `CORR = 0.50` 时的 5–95 区间为 old [0.12, 1.46]、average [−0.07, 2.43]、new [−0.03, 1.78]，
  且"看起来越过代理"的那个分区在单次抽样与中位数之间会改变。就幅度而言，old 分区的位移 −0.1444
  相当于 1.29 个后验 SD，即与后验宽度可比而非埋没其中。拟合收敛到的是一个
  **方向，不是一个被辨识出来的有效系数**。
- **网格搜索（Step 5e）**：恢复到最近网格节点是由网格围绕真值摆放保证的，所以确定性的"三个系数全
  恢复"是网格摆放的产物；只有加权集合才能谈可辨识性。
- 直接回应 §3.3（"报告行为集合距真实场的任何简单平均有多远"）：当非均质性不相关时距离≈0，当它相关
  时是一个清晰的、被解决的、朝长度加权代理的位移。**是非均质性中的结构、而不是非均质性本身，破坏了
  平均效应** —— 这里是用一种合成的管长相关性检验的，它是一个结构化代理，**不是**已被证明的流径或
  停留时间加权。old 分区的低残差截断是另一个"精确但有偏"的来源（→ Step 9）。

| 0.02 | 37.0 | 3.8 | 2.0 | 97% | 15% [12–17] | 17% [12–20] | 19% [15–21] | 0.020 |
| 0.05 | 699.1 | 94.4 | 32.0 | 7% | 42% [32–48] | 47% [36–52] | 44% [37–52] | 0.053 |
| 0.10 | 4218.0 | 1285.7 | 1157.9 | 0% | 65% [63–72] | 91% [83–94] | 87% [81–91] | 0.087 |
| 0.15 | 6482.6 | 5137.4 | 3743.6 | 0% | 81% [77–88] | 98% [95–99] | 97% [95–98] | 0.126 |

非正式与正式后验 SD 之比 —— 也就是"所要求的精度"中有多少属于评分而不属于传感器：
σ = 0.02 时 **×3.9 / 5.3 / 5.8**，0.05 时 **×3.3 / 3.2 / 3.0**，0.10 时 **×2.4 / 3.1 / 3.0**，
0.15 时 **×2.1 / 2.2 / 2.3**（old / avg / new）。

传感器精度敏感性

结论：

1. **σ = 0.10 的传感器已经是有用的，而早先"它不够用"的结论是评分规则造成的产物。** 在主规则下，
   一台 σ = 0.10 的仪器把 old / average / new 的先验宽度分别保留到 27 / 30 / 29 % —— 三者都被很好地
   告知。非正式对照在**同样的观测**上报告的是 65 / 91 / 87%，正是它产生了早先"需要 σ ≲ 0.05"的建议。
   因此所需精度比先前报告的**宽松**，而早先那个数字**不应再被引用**。
2. **两种规则下预测不确定性都大致随 σ 线性增长**，但水平不同：在风险主导的 old 分区节点 15 处，
   5–95% 带在主规则下从 0.006 增长到 0.051 mg/L，在对照下则是 0.020 到 0.126。
3. **最紧的两行在主规则下受蒙特卡洛限制，这是一个锐利似然作用在固定先验库上的诚实代价。** σ = 0.05
   时 ESS 中位数是 20.9，σ = 0.02 时是 1.8，也就是说基本上是一个成员扛着整个后验。它们 13% 和 4%
   的"SD 保留比"因此**不是**对这类传感器能买到什么的测量 —— 有效成员这么少时，后验宽度是被**低估**
   的。这两行在 artifact 中都按图上阴影所用的同一 ESS 判据标记为 `sampling_limited`。要把 σ ≤ 0.05
   量化清楚，最好用**适应似然的设计**（重要性抽样、序贯或自适应抽样）。加大均匀抽样也行，但低效，
   而且值得把话说准：因为 ESS 占比大致恒定，绝对 ESS 随库容量**线性**增长，所以要达到 ESS ≈ 100 的
   判据，σ = 0.05 时需要约 **5 倍**的库，σ = 0.02 时需要约 **55 倍**。按当前库实测的成本折算，前者
   是几十分钟和几百 MB，后者是数小时和数 GB —— 是**昂贵且浪费**，而不是不可能。早先"蛮力解决不了"
   的说法太强了：均匀抽样确实能解决，代价随似然的锐利程度上升，而这恰恰就是"应该让抽样器去适应它"
   的论据。
4. **对照组真正重要的诊断量是它的最小 ESS，而不是中位数。** σ = 0.05 时它的中位 ESS 是 699，但最差
   的一次实现只有 32，且有 7% 的实现低于 100。只用中位数总结这一行，会显得从容解决，而实际上每十四
   次中就有一次没有。

**所需精度的结论（回邮件），修订版。** 在主分析的正式似然下，一台 **σ ≈ 0.10 mg/L** 的仪器 ——
常见的商用级别 —— 已经能把三个分组系数都约束到先验宽度的三分之一以内，并支撑风险格局；在
**σ = 0.15** 时宽度增长到 38–45%，标定带来的增量明显减少。更精密的传感器原则上有帮助，但**本研究
无法说明帮助多少**，因为在 σ ≤ 0.05 时答案受限于先验抽样设计而非测量本身。**绝不能重复**的是早先
那个"需要 σ ≲ 0.05 才能得到有用预测"的说法：那是非正式评分的低效，被用传感器单位量了出来。本节
取代了 §3.5 中标记的、从基础 notebook 引入的噪声扫描。

## Step 7 —— 先验可辨识性：Fisher 信息 / CRLB

**三种分析的角色（务必区分）。** Fisher/CRLB（Step 7）是***先验的***（a priori）—— 它只用模型、
敏感度和假定的噪声水平，不用任何实际观测集，因此它在标定**之前预测**可辨识性。剖面似然（Step 7b）
使用**实际观测**的数据，因此是一个***实用 / 后验***的可辨识性检查（正式似然的验证），**不是**预测。
**从这里开始严格使用的命名**：**正式似然加权集合**是主要经验结果，**非正式 GLUE 行为集合**是对照。
"baseline GLUE"这个说法不再使用，因为它同时指代一个配置和一个推断规则，而这两者已经分家。在基线
模型上（k_b 固定、无偏置），同类可比的链条因此有四环：**Fisher Case A → 正式剖面似然 → 正式似然
加权集合 → 非正式 GLUE 行为集合**，最后一环仅作对照。Cases B/C 是**扩展模型**（现实性）的预测。

**两层读法（论文结构）—— 保持分开；绝不可合并起来论证非正式 GLUE 行为集合"更真实"。**

- *第 1 层 —— 受控基线的可辨识性*（条件完全相同：k_b 固定、传感器无偏、独立高斯噪声、只有三个
  k_w）：Fisher **Case A**（先验预测）↔ 正式**剖面似然**（后验验证）↔ **正式似然加权集合**（主要
  经验结果）↔ **非正式 GLUE 行为集合**（对照）。最干净的结论：*数据携带了关于三者的信息；正式似然
  把它提取了出来；非正式 GLUE 明显更宽、更依赖先验。*
- *第 2 层 —— 现实性敏感性*：Case **B**（+k_b）、Case **C**（+6 个监测点偏置）、**AR(1)**（Step 7c）
  和截尾似然（Step 9），每一个都*单独*放松一条基线假设。结论：*理想可辨识性对真实误差源是脆弱的
  —— 尤其对 avg/new —— 而 old 相对稳健。*

这些基线假设对本受控合成实验而言是**按构造成立的**（k_b 就是固定的，噪声就是按独立高斯生成的，
没有注入任何偏置），因此 **Case A 在这里是完全正确的** —— 它们只是对**真实网络部署而言过于乐观**。
所以要写"对受控基线有效，但对真实网络应用过于乐观"，**而不是**"这些假设是错的"。

**归一化约定（好让两张表读法一致）。** Step 7 报告的是 **1σ** 比值 `CRLB SD / 先验 SD`；Step 7b
报告的是 **95%** 区间。对均匀先验，`先验 SD = 半宽/√3`，而 95% 半宽 `= 1.96·SD`，所以两种约定相差
约 `1.96/√3 ≈ 1.13`。old 的 `0.25`（1σ CRLB/先验 SD）与它的连续截尾剖面
`±0.1807 / 0.65 ≈ 0.28`（95% 半宽 / 先验半宽，恰好是 `0.25 × 1.13`）因此描述的是
**同一个紧致程度的两种表达**，而不是字面上同一个比值。**绝对区间**和 **CRLB/先验 SD** 两者都报告
—— 绝不只报归一化数字。

真值处的敏感度 `J[r,j] = ∂C_r/∂k_j`（中心差分；r = 6 监测点 × 49 h = 294）、Fisher 信息
`F = Jᵀ J / σ²` 以及 CRLB（可达到的最小 SD）。三个 k_w 的 CRLB 是在逐层加入评审所提混杂因素的嵌套
模型下计算的，用的是边际（Schur）信息 `F_pp − F_pn F_nn⁻¹ F_np`（`step7_fisher.py`，σ = 0.10；
假设噪声独立 —— AR(1)（#4）在 **Step 7c** 中单独量化）：

- **A** 只有 k_w（k_b 已知、无偏置）—— 理想化的最好情形
- **B** + k_b（k_b 与 k_w 互相权衡 —— Priority-2 #5）
- **C** + 6 个逐监测点偏置（系统性传感器偏置 —— Priority-2 #1）

**有限差分步长按尺度设定**，不共用：`H` = 0.02 / 0.005 / 0.0025 m/day，分别对应 old / average / new
（`wq_common.FD_STEP`），即各自真值的 2 / 5 / 5%，另外 `k_b` 用 0.05 day⁻¹。若用单一共享步长，对
`old` 是 2% 的扰动，对 `new` 则是 40% 的扰动。

直接敏感度检查（`step7_verify.py`；把一个系数移动 ±H、其余保持真值时，任一监测点上的最大 |ΔC|）：
**old** 只影响它自己分区的节点 15/145，在 0.04 的变化上移动 0.0075；**average** 使 209/231 在 0.01
上移动 0.0130；**new**（近源）使整个网络的节点移动，在 0.005 上移动 0.0106。换算成每单位系数即
**0.19 / 1.30 / 2.12 mg/L per m/day** —— new 和 average 的单位敏感度**最高**（近源管段位于整个网络
的上游），old 大约只有 new 的十分之一。

| 情形 | old | average | new | 条件数 |
| --- | --- | --- | --- | --- |
| A —— 只有 k_w | 0.25 ✅ | 0.29 ✅ | 0.29 ✅ | 215 |
| B —— k_w + k_b | 0.30 ✅ | 0.54 ✅ | 0.54 ✅ | 101 |
| C —— k_w + k_b + 偏置 | **0.67 ✅** | **2.24 ❌** | **1.09 ❌** | 88 |

（数值 = CRLB SD / 先验 SD，是 **1σ** 比值；**< 1** 表示数据*原则上*能把该系数压到先验以下 ——
这是一个启发式判据，不是严格定理。）

**正式集合的离散度与 Case-A CRLB 局部一致。** 这是把"GLUE vs Fisher"的争论作为**一致性**读法收尾的
检查（**不是**频率学派意义上的有效性证明 —— 那需要 Step 14 的重复抽样检验）：

| 系数 | Case-A CRLB | 正式截尾集合 SD | 比值 | 非正式 GLUE SD |
| --- | --- | --- | --- | --- |
| old | 0.09473 | 0.09380 | **0.99** | 0.26679 |
| average | 0.01351 | 0.01416 | **1.05** | 0.04240 |
| new | 0.00796 | 0.00776 | **0.98** | 0.02419 |

old 的 Case-A CRLB 为 0.09473（见表）。正式加权集合的经验离散度在这一次实现上落在该界限的 1–5%
以内。非正式评分在**同样的观测**上给出的是该界限的 2.8–3.1 倍。所以长期存在的"GLUE 比 CRLB 宽三倍"
这个差距，**从来不是**数据缺乏信息的证据，也不是 Jacobian 的 bug：它是**评分的统计低效**。只有正式
那几行与 CRLB 是同类可比的。

含多余参数的 Fisher/CRLB

**Case A 是两个基线集合共同的同类可比基准** —— 正式似然加权集合和非正式 GLUE 对照都是，因为两者都
固定 k_b、都假设无传感器偏置。Cases B 和 C 是**现实性敏感性分析**，不是对任何一个集合的描述。

结论：

1. **理想情形 A —— 数据确实包含关于三者的信息**（CRLB/先验 0.25/0.29/0.29 < 1）。事实上 new/avg 的
   *单位敏感度更高*（近源管段位于整个网络上游；2.12 和 1.30 对 0.19 mg/L per m/day）。所以观测**并非
   根本上缺乏**关于 avg/new 的信息。
2. **A 与 GLUE 之间的差距完全是评分造成的，而这一点现在是被证明的，不是被论证的。** 非正式 GLUE 同样
   固定 k_b、同样忽略偏置，所以它的同类基准就是 A；它给出 0.71/0.92/0.88，而界限是 0.25/0.29/0.29。
   正式集合在**同样的数据**上给出 0.25/0.31/0.28 —— 与界限相差 5% 以内。此前为这个差距提出的其他解释
   （阈值、零截断、非线性、有限抽样、old 的单边响应）因此至多是二阶的：**从似然中丢掉因子 `N`**
   就足以解释它，正如 Stedinger 2008 / Mantovan & Todini 2006 所预言。它**绝不能**归因于 k_b 或偏置
   —— 两者在两个集合中都不存在。
3. **敏感度 ≠ 可辨识性。** new/avg 的单位响应更大，但它们的响应*模仿*了全局 k_b 变化或逐监测点偏置
   （非唯一），很容易被混淆；old 的响应更小但**有特征**（局限在 15/145，具有特定的时空形状），因此
   它能在混杂中存活。这就是为什么 old 尽管原始敏感度更低，却是稳健可辨识的那一个。
4. **现实性敏感性（B、C）。** 允许 k_b 不确定（B）会把 avg/new 的 CRLB 放大 1.8–1.9 倍，而 old 只放大
   1.2 倍；再加入逐监测点偏置（C）会把 **avg（2.24）和 new（1.09）推到其先验之上 → 实际不可辨识**，
   而 **old 保留有限的可辨识性（0.67）**。因此 Case C 复现了一个与非正式 GLUE 对照*定性相似*的梯度
   —— 但那是在一个**两个基线集合都没有使用过的扩展多余参数模型**下，所以它是**佐证了这个梯度的稳健性**，
   而不是"确认"了任何一次基线运行。
   **这里有两个量极易混淆，而且符号相反**（`step7_verify.py` 会并排打印两者）。Jacobian 列的余弦
   `F_ij/√(F_ii F_jj)` —— 两个*敏感度方向*有多共线，是**设计的属性** —— 对 old / average / new 相对
   `k_b` 分别是 **+0.333 / +0.770 / +0.831**。而从 `Cov(θ̂) ≈ σ²(JᵀJ)⁻¹` 归一化得到的*估计量*相关
   系数是 **−0.547 / −0.839 / −0.842**。承载体相–壁面补偿这个故事的是那个**负的估计量相关**（更弱的
   固定 `k_b` 会买来更强的 `k_w`，这正是 Step 8b 所测量的），而且只有它才配叫参数相关。本日志的早先
   版本把余弦当作相关系数报告了。
5. **原始矩阵上的条件数主要是单位造成的假象。** Case A 的 κ ≈ 215 看起来像是一个病态问题，但三个系数
   的尺度相差 20 倍，所以未归一化信息矩阵的特征值混合了量级和几何。把参数按其先验 SD 重新标度使其
   无量纲：

| 形式 | 特征值（Case A） | 条件数 |
| --- | --- | --- |
| 原始 | 23906 / 5106 / 111 | **215** |
| 先验标度 | 24.5 / 16.6 / 7.6 | **3.2** |

   在无量纲矩阵上，跨度是 **3.2** 倍而不是 215，所以三个系数被告知的程度远比原始数字所暗示的更接近。
   这也限定了评审从运行 notebook 里引用的那句表述 —— "三个分区系数的特征值跨越三个数量级" ——
   那是一句关于**单位**的陈述，不是关于可辨识性的。以先验 SD 为单位，最"松"的方向是
   `old −0.297, average −0.663, new +0.687`：本质上就是 **average 与 new 之间的权衡**，也正是其他每
   一项诊断都发现的那个混杂。另外注意，B/C 的 κ *更小*并不意味着可辨识性更好 —— κ 只反映各方向之间
   的相对失衡，而加入多余参数会**降低总信息量**。
6. **有限差分步长不是这一切的驱动因素。** 单一共享的 `H = 0.02` 对 old 真值是 2%，对 new 真值却是 40%，
   所以步长现在**按尺度设定**（0.02 / 0.005 / 0.0025，即各自真值的 2 / 5 / 5%），而且每个系数还在其
   默认值附近的一系列步长上重新做了差分：

| 系数 | 默认步长 | 测试的步长 | 占真值百分比 | 扫描中 Case-A CRLB 的变幅 |
| --- | --- | --- | --- | --- |
| old | 0.02 | 0.005 – 0.04 | 0.5 – 4% | **0.10%** |
| average | 0.005 | 0.002 – 0.02 | 2 – 20% | **1.00%** |
| new | 0.0025 | 0.001 – 0.01 | 2 – 20% | **1.14%** |

   在步长变化四倍到十倍的范围内，CRLB 只变动约 1%，所以导数是收敛的，即使在 20% 的扰动下，步长选择
   带来的误差也至多约 1%。这个顾虑是合理的，答案是**在此精度下它无关紧要** —— 但正是按尺度设定的
   步长才使各系数的 Jacobian 列首次可比，因此上面引用的原始 `max |ΔC|` 数字必须对照各自列的步长来读。

本节交付 Priority-2 #2（先验可辨识性），并链接到 #1（传感器偏置）、#5（k_b）和 #4（AR(1)，Step 7c）
这几项现实性分析。

**推荐的论文表述（可辨识性主线）。**

> 先验 Fisher 信息与正式剖面似然表明，在体相衰减固定、传感器无偏、误差独立高斯的受控基线假设下，
> 六监测点数据集包含了关于全部三个分组壁面反应系数的可辨识信息。非正式 GLUE 表述产生了明显更宽、
> 更依赖先验的行为分布，说明其加权方式和阈值没有充分利用 294 个残差中所含的信息。另外的现实性敏感性
> 分析表明，体相衰减的不确定性、监测点特定偏置以及时间自相关，都可能实质性地削弱这种理想可辨识性，
> 对 average 和 new 系数尤为明显，而 old 系数相对稳健。

**GLUE 是什么、不是什么。** 非正式 GLUE 集合是一个*保守的、依赖方法的行为包络*，全文作为**对照**
保留 —— 它与正式规则的对比本身就是一项结果。它**不是**风险传播的载体：所有头条风险和情景数字都来自
正式截尾似然（Steps 10 和 12），GLUE 在那里出现时都是作为并列的对照。它也**不是**对全部真实世界不确
定性来源的已标定表示（它忽略了 k_b 不确定性、监测点偏置、AR(1) 协方差和截尾）。它的宽度来自"非正式
似然 + 阈值 + 先验 + 有限抽样 + 非线性参数空间"，**不是**因为它建模了现实。

**不要写**："这些假设是错的"（在这里它们按构造成立）；"GLUE 的宽度 ≈ 真实世界的可辨识性"（无依据 ——
基线运行里根本没有那些多余参数项）；或"正式分析收敛到了 GLUE 的结果"（Case C 是一个*不同的、扩展的*
模型）。**要写**：Case C 产生了一个*定性相似*的可辨识性梯度（old 部分可辨识、avg/new 弱），**佐证了
该梯度的稳健性**，而不是确认了非正式 GLUE 集合。

## Step 7b —— 剖面似然（实用可辨识性，后验）

评审要求的第三个可辨识性工具。**角色**：与 Fisher/CRLB（先验）不同，剖面似然使用**实际观测**的数据，
因此是一个*实用 / 后验*的可辨识性检查（正式似然的验证），**不是**先验预测。对每个系数，固定它并
**对另外两个重新优化**（最小化 SSE），得到剖面负对数似然；95% 单参数区间是 `ΔNLL ≤ 1.92`。正式
似然 `NLL = (N/2σ²)·RMSE²`（N = 294，σ = 0.1），从一个 21³ 网格上读出（`step7b_profile.py`）。
与 Step 4b 的*扫描*（另外两个固定在真值）不同，剖面**允许参数之间互相补偿**。

**报告两个版本，因为网格那个是量化的。** 21 点网格在 `old` 方向的步长是 0.0650 m/day —— 比本日志中
讨论的好几个效应都粗（截尾位移是 0.012，结构增量约 0.01）—— 所以网格区间只能把端点放在真区间**内部**
的节点上，因而**系统性偏窄**。连续版本在每个目标值上用 Nelder–Mead 优化两个多余系数，并用 Brent
二分法在 `ΔNLL − 1.92` 上定位端点；共 **7792** 次不同的 EPANET 评估，在截尾和 iid 两种似然下各跑一遍。

| 系数 | 网格 95% | 连续 95% | 网格半宽 | 连续半宽 | 变化 | 端点移动 |
| --- | --- | --- | --- | --- | --- | --- |
| old | [−1.110, −0.850] | **[−1.1720, −0.8106]** | ±0.1300 | ±0.1807 | **+39.0%** | 0.78 网格步 |
| average | [−0.136, −0.088] | **[−0.1373, −0.0821]** | ±0.0240 | ±0.0276 | **+14.8%** | 0.45 网格步 |
| new | [−0.057, −0.034] | **[−0.0599, −0.0294]** | ±0.0119 | ±0.0152 | **+28.2%** | 0.70 网格步 |

主分析的连续剖面使用**截尾**似然；iid 连续曲线作为局部可辨识性基准保留（截尾的影响在 Step 9 中单独
分离）。`k_w,old` 的连续 95% 区间是 [−1.1720, −0.8106]。

**网格低估了每一个区间，在主规则下低估了约 15–39%。** 每个端点都向外移动了**不足一个步长**的距离
—— `old` 0.78 个网格步、`average` 0.45、`new` 0.70（半宽变化除以该系数自己的网格步长）—— 而且方向
**总是向外**。这两条性质都是**量化**的特征，不是噪声的特征：网格找不到落在节点之间的穿越点，于是停在
最后一个位于内部的节点上，因而偏差被一个步长所限。这个比例**三者并不相同**，所以不能当作单一数字引用。

真值 −1.0 / −0.1 / −0.05 在两个版本的每一个区间内都成立。**只应引用连续区间**，同样的告诫适用于从那个
网格上读出的任何其他东西 —— 这也是为什么 Step 7c 中 `old` 的 AR(1) 展宽因子（2.00×）**不应被当作物理
结果来读**：它的独立情形分母正是这些偏窄的网格区间之一。

剖面似然：与 CRLB 吻合的紧致双边区间

结论：

1. **在正式似然下三者都是紧致、双边可辨识的** —— 剖面 95% 区间都包住真值，且**与 Fisher CRLB 的 95%
   区间吻合**（Case A）。两个正式工具一致：观测**确实**辨识出全部三者（理想化条件，k_b 固定，无偏置）。
2. **参数补偿很小**：剖面（对另外两个重新优化）≈ 扫描（另外两个固定在真值），所以在这个理想化设定下，
   三个系数在正式似然下没有强烈混杂。
3. **old 的谷轻微不对称**（强侧更浅），这是它单边倾向的残留；但正式似然仍然给出双边界限。所以来自
   Steps 4/4b 的"单边"描述是一个 *GLUE / 非正式似然*的视角 —— 在高效的正式似然下，old 是双边的，
   只是强侧约束较弱。
4. **远比 GLUE 紧。** 这些正式区间远窄于 GLUE 行为分布（后者几乎无法收窄 avg/new）。差距来自 GLUE
   的非正式似然丢掉了 N = 294 这个因子（→ 过平）；剖面/Fisher 用的是完整的正式似然。这完成了
   Priority-2 #2 的第三环，也确认了 Step 7 对 GLUE 低效的诊断。
5. 与 Step 7 一样，这是**理想化**基准（Case A）；引入 k_b 不确定性和传感器偏置（Fisher Case C）
   才是把 avg/new 变成*实际*不可辨识的原因。

## Step 7c —— 误差自相关 AR(1)（第 2 层现实性）—— Priority-2 #4

上面两个正式工具都假设小时误差**独立**。真实遥测在时间上是自相关的，所以那些区间是一个**下界**。
这里不是机械地把每个 CRLB 乘上一个标量有效样本量因子，而是用 AR(1) 结构重建观测协方差并重新计算
Fisher 信息（`step7c_ar1.py`，Case A = 只有 k_w，ρ = 0.4）：

**协方差 / Fisher：**

```
每传感器 49×49 块    Σ_block[t,s] = σ² · ρ^|t−s|          （小时级 AR(1)）
完整协方差           Σ = block_diag(6 个传感器块)          （294×294，传感器之间独立）
Fisher (AR(1))       F_AR1 = Jᵀ Σ⁻¹ J        vs   独立情形  F = Jᵀ J / σ²
CRLB_j = √[ (F⁻¹)_jj ]
```

**标量参考（快速估算的告诫）：**

```
放大倍数 ≈ √[ (1+ρ)/(1−ρ) ] = √(1.4/0.6) ≈ 1.53
N_eff    ≈ N · (1−ρ)/(1+ρ) = 294 · 0.6/1.4 ≈ 126     （294 个小时点中）
```

| 系数 | CRLB 独立 | CRLB AR(1) | 展宽 | CRLB/先验 独立 | CRLB/先验 AR(1) |
| --- | --- | --- | --- | --- | --- |
| old | ±0.0947 | ±0.1406 | 1.48× | 0.25 | 0.37 |
| average | ±0.0135 | ±0.0201 | 1.49× | 0.29 | 0.43 |
| new | ±0.0080 | ±0.0114 | 1.44× | 0.29 | 0.42 |

结论：

1. **每个系数按*自己的*因子展宽**（1.44–1.49×），由完整协方差算出 —— *不是*对所有系数套用同一个
   机械的 1.53×。它们在这里接近标量参考，是因为六个传感器的时间 Jacobian 形状相似；协方差路线才是
   可辩护的做法，在敏感度随时间差异更大的场合它会把这些因子分得更开。
2. **AR(1) 本身只是一个*温和*的告诫。** 即使在 ρ = 0.4 下理想可辨识性依然存活（CRLB/先验 SD：
   old 0.37、avg 0.43、new 0.42 —— 全部仍 < 1）。所以自相关把理想化区间*放大*约 1.5 倍，但**并不会
   单凭它自己摧毁可辨识性**。
3. **主导的现实性削弱因素是 k_b + 偏置，不是 AR(1)。** 对比：Case C（k_b + 6 个偏置）把 avg 推到 2.24、
   new 推到 1.09（不可辨识；Step 7），比 AR(1) 的 ×1.5 大一个数量级。因此 AR(1) 是作为一个
   **已被量化的告诫**报告的，不是主导的现实性项。

**AR(1) 剖面似然 —— 一个粗略的敏感性分析，不是第二组主区间。** 下面的区间要当作**固定 ρ、未截尾、
受网格分辨率限制的敏感性分析**来读，**不能**与 Step 7b 的 95% 区间等量齐观。有三点把它们分开：
ρ = 0.4 是*假定的*，这些按 iid 生成的观测无法支持任何一个 ρ 值；目标函数是普通高斯的
`½·eᵀΣ⁻¹e`，**不是**别处作为主分析的截尾似然；端点来自 21³ 网格，而 Step 7b 已证明该网格系统性偏窄
15–39%。连续的截尾 AR(1) 剖面尚未实现，在实现之前，只应引用展宽的*方向和大致量级*。为了不让剖面这一
侧停留在"名义上"，21³ 网格已被重建，在每个节点上存储完整的 294 维残差向量 `e`
（`step7c_profile_ar1.py`），使 AR(1) 剖面能精确按 `NLL(θ) = ½·e(θ)ᵀ Σ⁻¹ e(θ)` 计算（随附的运行
notebook 使用同样的 AR(1) 观测过程）。独立情形的剖面复现了 Step 7b（合理性检查），而 AR(1) 剖面按其
自身的逐系数因子展宽：

| 系数 | 独立 95% | AR(1) 95% | 半宽 独立 → AR(1) | 展宽 |
| --- | --- | --- | --- | --- |
| old | [-1.110, -0.850] | [-1.240, -0.720] | ±0.130 → ±0.260 | 2.00× |
| average | [-0.136, -0.088] | [-0.144, -0.072] | ±0.024 → ±0.036 | 1.50× |
| new | [-0.057, -0.034] | [-0.067, -0.029] | ±0.012 → ±0.019 | 1.60× |

`old` 的 2.00× **不应被当作物理结果**：该方向的网格步长是 0.065 m/day，所以每个端点都被量化到约等于
所报半宽的一半，而两个被量化数字的比值是粗糙的。`average` 和 `new` 在更细的网格上，它们的剖面展宽
（1.50–1.60×）与 Fisher-CRLB 的展宽（1.44–1.49×）一致：两个正式工具对 AR(1) 的反应同样温和，而且真值
仍落在每一个 AR(1) 区间内 —— 所以 AR(1) 放大了但没有推翻理想可辨识性。（标量的
`√[(1+ρ)/(1−ρ)]≈1.53` 只是参考；上面的逐系数因子来自完整协方差。）

结论：

1. **系统性偏置以数倍的量压过随机离散度。** 节点 15 上 +0.05 mg/L 的偏移把 `k_w,old` 从 −1.0405 移到

   被低估了。正偏置（传感器读数偏高）会让拟合推断出**更弱**的衰减。
2. **只有被本地观测到的那个系数会动。** 在整个 ±0.10 扫描范围内 `avg`/`new` 的位移 ≤ 0.004 ——
   偏置腐蚀的是 `old`，不是其他两个。
3. **风险场比参数稳健得多。** 在 ±0.10 处，`k_w,old` 已经移动了将近 4 个后验 SD，而 92 节点风险排序
   相对无偏情形的 Spearman 仍是 0.999、Kendall ≥ 0.988，而且这在**两个**风险度量上都成立
   （`P_bar` ≥ 0.9993，`E[A]` ≥ 0.9996）。领先集合在 Step 10 所发布的亏缺度量上更稳健：按 `E[A]` 排序
   时，除 +0.10（Jaccard 0.71）外每个偏移下前 6 名都不变；而按 `P_bar` 排序时，它在 +0.05 就已经掉了
   一个节点。在 `P_bar` 上，所有**负**偏移下前 6 名集合都*不变*，在 +0.05 和 +0.10 各掉一个节点
   （Jaccard 0.71）。所以未经校正的传感器偏置会毁掉系数，却几乎不影响运行层面的优先级排序 ——
   这在运行上令人安心，同时也是一个"不要把系数当作物理量来读"的警告。
4. **形状 —— 评审是对的，我们最初的回答是错的。** 把偏移减半（0.05 → 0.025）保留了 **53%** 的位移：
   高于线性会给出的 50%，所以响应是**次线性/凹的**，与评审所说一致，只是比它引用的约 70% 弱一些。
   本节的早先版本报告的是*凸/39%*。那个数字来自非正式 GLUE 评分，它的平坦性不仅缩小了位移，还**颠倒
   了曲率**。这是非正式评分**第三次**推翻结论，前两次是 Steps 3 和 5c。
5. **响应是不对称的，原因是截尾。** `|负| / |正|` 的位移比在 ±0.025、±0.05 和 ±0.10 处分别是
   1.14、1.19 和 0.99，而落在传感器下限上的观测数在整个扫描中从 13 降到 5。负偏移把观测推到下限上，
   而一个被截尾的点携带的信息与未截断的点不同。**因此偏置结果必须始终带符号引用；单个 ± 数字没有
   意义。**
6. **Step 7 Case C 的经验对应物。** Fisher 显示逐监测点偏置会*吸收*信号（avg/new → 不可辨识）；本节
   显示一个真实的偏移会*使最稳健可辨识的那个系数产生偏差*。真实偏置是可以通过参比取样估计并校正的
   —— 那是运行 notebook 里的 QA 步骤；本节量化的是**未校正**时的影响。这里只建模了恒定偏移，不含漂移。

### 为什么选节点 15，位置重要吗？（偏置位置扫描，`step8c_bias_bynode.py`）

同样的偏移被依次注入六个监测点（每个分区两个：new 107/113，old 15/145，average 209/231），**双向**，
在**正式截尾加权**下，30 次噪声实现，风险场取它们的中位数。基线（无偏）正式均值为
old −1.0405 / average −0.1028 / new −0.0509，后验 SD 分别为 0.1012 / 0.0136 / 0.0080 m/day，而且已有
中位 7 个观测落在传感器下限上。

自身系数的位移（以后验 SD 计，指被偏置监测点所在分区的那个系数）：

在全部 24 个正式行中，92 节点风险排序相对无偏情形在两个度量上都保持 Spearman **≥ 0.999**
（`P_bar` 最小 0.9993，`E[A]` 最小 0.9995），所以**全网排序从不移动，只有领先集合可能移动**。

上表的 Jaccard 列是 `P_bar` 的。**在 `E[A]`（Step 10 头条表格所用的排序度量）上，24 个分支中有 23 个
前 6 名不变** —— 唯一的例外是节点 15 在 +0.10 处掉了一个节点（Jaccard 0.71）。所以按深度加权的严重度
排序时，候选名单对传感器偏置明显更稳健；下面那四个"正向 0.71"的条目是 `P_bar` 现象。

结论（位置确实重要，但不是早先那张非正式表格所暗示的方式）：

1. **偏置主要腐蚀它自己分区的系数，但外溢并非可以忽略。** 最大位移永远是自身分区的那个，但偏置一个
   *new* 分区监测点会让 `average` 移动最多 2.0 SD，偏置一个 *average* 分区监测点会让 `new` 移动最多
   2.7 SD。以 m/day 的绝对值看外溢很小；以受影响系数自身的离散度为单位看则不小。这正是 Step 7 最"松"
   的那个特征方向所指认的 `average`↔`new` 混杂，从数据侧看到的样子。
2. **归一化后最严重的腐蚀不在节点 15。** 以后验 SD 计，破坏力最大的单个传感器是
   **231（average 分区）：在 −0.10 mg/L 时达 −5.94 SD**，其次是 113（new，−4.44 SD）；节点 15 达到
   −3.82 / +3.87 SD。节点 15 仍然是 Step 8 合适的**头条**案例 —— `old` 是物理上主导、也是最稳健可辨识
   的系数 —— 但它不是最糟的位置；而早先"avg/new 几乎没有反应"的说法是非正式加权造成的产物，那种加权
   恰恰把被弱告知的系数压平了。
3. **同一分区内的两个监测点是不同的**（113 > 107；231 > 209；15 > 145）—— 局部敏感度和信息含量不同，
   所以**是哪个**传感器漂移、而不只是哪个分区，会让影响幅度相差最多 3 倍（231 对 209）。
4. **响应是符号不对称的**，原因是截尾：负偏移把观测推到传感器下限上（节点 15 在 −0.10 处中位截尾数
   升到 13），正偏移则把它们抬离下限（降到 4–5）。在十二个"节点 × 幅度"组合中有十一个是负向位移更大；
   例外是节点 15 在 ±0.10 处（−3.82 对 +3.87），这与 Step 8 自身扫描在该幅度记录的 `|负|/|正| = 0.99`
   是同一件事。**偏置结果必须带符号引用。**
5. **风险产品在排序上稳健，但在前 6 名成员上不稳健。** 两个度量上 Spearman 都从未低于 0.999；在
   `E[A]` 上 24 个分支中只有一个改变了领先集合（节点 15，+0.10）。在 `P_bar` 上：每一个*负*偏移都让
   前 6 名集合保持完整；而四个 new/old 监测点上的*正*偏移，以及 209 上的 +0.10，各替换掉一个热点
   （Jaccard 0.71）。只有节点 231 在所有偏移下都不改变该集合。所以**单个漂移的传感器能在不扰动全网
   格局的情况下重排热点名单的边缘部分**。

9. **该怎么写。** `k_b` ±20% 的错误设定会让 average 和 new 系数移动 1.4–1.6 个后验 SD，并使**全网尺度**
   的风险排序在两个度量上都保持高度秩相关。它对**运行候选名单**的影响**取决于度量**：在时间平均的
   低氯概率 `P_bar` 上，前 6 名在两个符号下都丢掉六个中的两个，且重排远远越过截断点；在 Step 10 所
   发布的累积亏缺排序 `E[A]` 上，前 6 名在 −0.4 时不变，在 −0.6 时以一次第六/第七名交换丢掉一个节点。

   度量的情况下都不成立。**
10. **本诊断的限定条件。** 两个排序都来自 30 次实现的中位数风险场，所以它们继承了中位数所抹平的一切；
    逐次实现的排名稳定性没有报告。`P_bar` 第 4–6 名的近乎并列意味着那三个节点的*排名*本身就几乎不
    携带信息 —— 这是一个"发布候选名单时应同时给出风险数值而非只给排名"的论据。Steps 8、8c 和 8d 现在
    也都报告两个度量，而这里打开的缺口正朝令人安心的方向收拢：在 `E[A]` 上，传感器误差这一族几乎不
    触碰领先集合（Step 8c 中 24 个分支有 23 个不变；Step 8d 中没有任何漂移分支改变它），所以
    **`k_b` 错误设定是本日志中唯一一个能移动按亏缺排序的候选名单的扰动**，而且也仅在一个符号下产生
    一次边界交换。

## Step 8d —— 传感器**漂移**，一个随时间变化的偏移 —— Priority-2 #1 后半

Steps 8 和 8c 建模的是**恒定**偏置。评审的意见标题是"系统性传感器误差（偏置、**漂移**）"，而一个正在
漂移的探头 —— 结垢，或者老化的标定 —— 才是更常见的现场失效模式。本节补上这一半
（`step8d_sensor_drift.py`；正式截尾加权，30 次噪声实现，复用缓存所以不重跑 EPANET）。

**排序依据，之所以要写明是因为有两种可能。** 前 6 名集合和 Spearman/Kendall 那几列都读自
**30 次实现的中位数风险场**。另一种做法 —— 跨实现的**众数**前 6 名*排序* —— 回答的是另一个问题，
被单独存为 `modal_top6_across_realisations`。本节和 Step 8 的早先版本用中位数场算秩相关、却用众数集合
算 Jaccard，同时声称两者都基于中位数；这已经修正，而且事实证明二者在这里的 24 个分支（以及 Step 8 的
全部 7 个）上**对集合都是一致的**，只在其中一个分支的内部次序上不同。所以本节没有任何数字改变 ——
但一张两个排序列建立在不同基础上的表格，即便碰巧一致也是站不住的。

**公式** —— 漂移是评估窗口内的一段线性斜坡：

```
b(t) = D · (t − t₀) / 48,        t ∈ [120, 168] h
```

**性质**：

- 传感器在窗口起点读数正确，到终点时偏离 `D`，所以它在窗口上的**均值**偏移是 `D/2`。
- 一个漂移既有均值也有形状。为了把两者分开，每个漂移分支都对照**同样噪声下的两个恒定偏置控制组**：
  `const(D/2)`，即*均值等效*；以及 `const(D)`，即*末值等效*。如果漂移落在 `const(D/2)` 上，那就只有
  它的均值重要，Step 8 已经涵盖了它；如果它更接近 `const(D)`，那时间结构本身就有独立意义。
- 双向，理由与 Step 8 的截尾理由相同。两个位置：节点 15（old，Step 8 的头条）和节点 231（average，
  Step 8c 发现归一化腐蚀最大的位置）。

自身系数的位移（以后验 SD 计；基线 SD：old 0.1012，average 0.0136 m/day）：

| 被偏置节点 | D | 漂移 (0→D) | const(D/2) | const(D) | 漂移 / const(D/2) | 截尾点数（漂移） |
| --- | --- | --- | --- | --- | --- | --- |
| 15 (old) | −0.100 | −2.34 | −2.59 | −3.82 | **0.90** | 10 |
| 15 (old) | −0.050 | −1.17 | −1.32 | −2.59 | **0.89** | 8 |
| 15 (old) | +0.050 | +1.05 | +1.16 | +2.19 | **0.90** | 6 |
| 15 (old) | +0.100 | +1.99 | +2.19 | +3.87 | **0.91** | 6 |
| 231 (average) | −0.100 | −3.19 | −3.25 | −5.94 | **0.98** | 7 |
| 231 (average) | −0.050 | −1.52 | −1.55 | −3.25 | **0.98** | 7 |
| 231 (average) | +0.050 | +1.41 | +1.44 | +2.72 | **0.98** | 7 |
| 231 (average) | +0.100 | +2.68 | +2.72 | +4.22 | **0.99** | 7 |

传感器漂移对照其均值等效和末值等效的恒定偏置控制组

**内建的交叉检查。** `const(D)` 那一列**精确复现**了 Steps 8 和 8c —— 节点 15 在 −0.10 给出 −3.82 SD、
在 +0.10 给出 +3.87 SD；节点 231 在 −0.10 给出 −5.94 SD —— 而且每个 `D` 处的 `const(D/2)` 都等于
`D/2` 处的 `const(D)`（节点 15：两条路都是 −2.59）。所以三个 step 脚本在共享条件上是**真正一致的**，
而不只是叙述上不矛盾。

结论：

1. **一个漂移在很好的近似下就等于它自己的均值。** 漂移位移是均值等效恒定位移的 **0.89–0.91**（节点 15）
   和 **0.98–0.99**（节点 231，在 D = +0.10 处比值达到 **0.9851**），大约是末值等效的一半。所以恒定
   偏置分析并不是与漂移不同的另一种现象：在 1–11% 的误差内，它**就是**漂移分析，只是在漂移的均值处
   求值。因此 Step 8 的扫描是可迁移的，评审"偏置、漂移"这个并列得到了完整而非一半的回答。
2. **它偏离自身均值的地方，原因是截尾。** 节点 231 的截尾数在每个分支上都是平坦的 7，其比值为
   0.98–0.99；节点 15 的截尾数在各分支间从 6 → 10 → 13 变化，其比值降到 0.90。一段斜坡只有部分时间
   处在极端偏移上，所以它截断的观测比同样末值的恒定偏置更少 —— 而在一个浓度已经接近传感器下限的
   old 分区监测点上，这会改变似然得到多少信息。残差在节点 15 处为 0.11–0.25 个后验 SD，在节点 231 处
   为 0.03–0.06 SD。
3. **这个偏离是带符号的，不对称。** 对负的 `D`，漂移造成的损害*小于*其均值等效（残差 +0.15 到
   +0.25 SD，朝无偏值方向）；对正的 `D`，它造成的损害*更大*（−0.11 到 −0.19 SD）。与 Steps 8 和 8c
   是同样的不对称、同样的原因。
4. **风险产品的表现与恒定偏置下完全一样。** 全部 24 个分支相对无偏情形在两个度量上 Spearman 都
   ≥ 0.999。**在 `E[A]` 上没有任何漂移分支改变领先集合** —— 整张表里唯一的 0.71 来自节点 15、+0.10 的
   末值等效*恒定*控制组 —— 所以这个量级的传感器漂移**不会触碰** Step 10 发布的候选名单。在 `P_bar` 上，
   除节点 15 在 +0.10 漂移处（Jaccard 0.71）外，前 6 名集合处处不变 —— 换掉一个节点，与正向恒定偏移
   产生的边缘效应相同。
5. **本节建模了什么、没建模什么。** 只测试了评估窗口内的*线性*斜坡，且漂移从零开始。窗口开始时已经
   部分发展的漂移属于 `const(D₀) + 斜坡` 的情形，没有跑；阶跃变化、非单调偏离、结垢曲线也都没有跑。
   被支持的论断是狭义的那个：**对单调漂移，估计所响应的是它在标定窗口上的均值偏移。**

## Step 9 —— 对零下限截尾的敏感性（零截断观测，L = 0）

草稿把观测生成为 `C_obs = max(0, C_true + ε)` —— 一个在 **L = 0** 处的硬下界 —— 然后用不加权的 RMSE
标定，也就是把每个被截断的 `0` 当作*精确*测量值。对被截断点的统计一致处理是把它当作*左截尾*：潜在
读数 `Y* = μ + ε` 只被观测到 `Y* ≤ 0`，因此它对似然的贡献应该是 `Φ(−μ/σ)`，而不是 `(0 − μ)²`。这就是
评审要求的稳健性检查 —— 在**同一批数据、L = 0** 上执行（`step9_zeroclip.py`）。

**Tobit 型截尾高斯似然（L = 0）** —— 作用在非线性 WNTR 预测上的截尾高斯（所以是 "Tobit-*型*"，
不是经典的线性 Tobit 回归）：

```
未截尾 (obs > 0)：  高斯       →  −½·((obs − μ)/σ)²
截断为 0 (obs = 0)： P(Y* ≤ 0)  →  log Φ(−μ/σ)          [scipy log_ndtr]
```

由于 σ 固定，最小化高斯 NLL 对参数的排序与最小化 SSE/RMSE 完全相同，所以"朴素"那一支就是草稿 RMSE
处理方式的正式高斯对应物。

**被截断为零的点的普查（实际标定数据）：**

| 范围 | 截断为零的点 | 说明 |
| --- | --- | --- |
| 全记录（6 × 169 h） | **43 / 1014** | 整个 168 h 模拟 |
| 标定（6 × 49 个预热后小时） | **10 / 294** | 实际用于拟合的点 |
| 按节点 | 15 (old): 6，145 (old): 3，231 (average): 1 | old 9 个，average 1 个，new 0 个 |

在修正后的预热下，截断**不再局限于 old 分区**：现在有一个点落在 average 分区的监测点上。到 120 h 时，
average 分区的浓度已经降到足以偶尔触及传感器下限，而 24 h 窗口从未显示过这一点。

**朴素当作精确 0 vs 在 0 处截尾（30 次噪声实现的中位数 [四分位距]）：**

| 系数 | 真值 | 朴素 中位数 [IQR] | 截尾 中位数 [IQR] | Δ 中位数 |
| --- | --- | --- | --- | --- |
| old | −1.0 | −1.0289 [−1.1180, −0.9700] | −1.0405 [−1.1324, −0.9850] | −0.0116 |
| average | −0.1 | −0.1027 [−0.1122, −0.0952] | −0.1028 [−0.1122, −0.0953] | −0.00003 |
| new | −0.05 | −0.0510 [−0.0566, −0.0434] | −0.0509 [−0.0564, −0.0433] | +0.00007 |

- 节点 15 低于 0.2 的小时比例：朴素 `0.470` vs 截尾 `0.470`（相同）；
- 高风险前 3 —— 在**正式似然加权集合**下按全部 8192 个候选的期望低于 0.2 mg/L 时间比例排序：
  **131, 141, 129 —— 两种估计量下完全相同**，而且现在也与 Step 10 的主风险图相同，因为两者都用正式
  加权；
- old 的剖面 95% 区间（基线）：朴素 `[−1.110, −0.850]` = 截尾 `[−1.110, −0.850]`。

上面这两个剖面区间*完全相等*是**网格的分辨率产物，不是零结果**：21 点网格在 `old` 方向的步长是
0.065 m/day，是那个 −0.0116 位移的五倍，所以**任何基于网格的区间都不可能记录到它**。Step 7b 的**连续**
剖面没有被量化，确实能分辨出来 —— 在同一批数据上分别用两种似然运行，它给出 `old` 的截尾区间
[−1.1720, −0.8106] 对 iid 区间 [−1.1517, −0.7973]，即整个区间朝更强衰减方向移动了约
0.013–0.020 m/day，半宽从 ±0.1772 增长到 ±0.1807（+2.0%）。`average` 和 `new` 的移动远小于其半宽的
百分之一。所以正确的表述是：**基于网格的剖面无法分辨截尾修正，而连续剖面显示出一个温和的位移和轻微
的展宽，且集中在 `old` 上** —— 这在符号和量级上都与下面的加权均值比较一致。

零截断普查（10/294）与 L=0 处的 old 剖面：朴素 vs 截尾的重叠

结论：

1. **294 个标定点中有 10 个被截断，它们集中在（但不再局限于）old 分区**：9 个在 old 分区监测点
   （15 和 145），**1 个在 average 分区监测点 231**（全记录 1014 个点中 43 个）。在草稿被取代的 24 h
   预热下，全部 8 个截断点都在 old 分区；到 120 h，average 分区已经耗竭到偶尔触及传感器下限。new 分区
   仍然从不截断。
2. **截尾修正很小但可测量，而且它只作用在 `old` 上。** 截尾似然把 old 的中位数从 −1.0289 移到 −1.0405，
   位移 **−0.0116** m/day，同时把 `average` 和 `new` 留在 0.0001 以内不变。节点 15 的风险（0.470）和
   前 3 风险排序（131, 141, 129）在两者下相同。所以草稿的 `max(0, ·)` + 不加权 RMSE 的选择**没有让主要
   结论产生偏差** —— 但"没有产生偏差"不等于"没有影响"，而它确实产生的影响，其量级与本日志讨论的其他
   几个量相当。
3. ***网格*剖面区间完全相等是分辨率产物，不是零结果。** 两种估计量在 21 点网格上都给出 `old` 的
   `[−1.110, −0.850]`，读起来像是完美吻合。**它不是**：网格在该方向的步长是 0.065 m/day，是那个
   −0.0116 位移的**五倍**，所以任何基于网格的区间都不可能记录到它。连续剖面（Step 7b）没有被量化，
   确实记录到了 —— `old` 的截尾区间 [−1.1720, −0.8106] 对 iid 区间 [−1.1517, −0.7973]，朝更强衰减位移，
   半宽宽 2.0%。**要引用就引用加权均值的比较；如果要引用剖面，只引用连续的那个；绝不要把恰好重合的
   *网格*区间当作等价性的证据。**
4. **为什么效应在这里很小 —— 以及为什么这不是一般性的等价。** 有两个针对本设置的原因：(i) 截断很罕见
   （`10/294 ≈ 3.4%`，所以 284 个未截尾点主导了似然）；(ii) 一个被截断为 0 的点所在之处，真实浓度本来
   就已经 ≈ 0，所以"恰好为 0"和"≤ 0"对一个接近 0 的模型 `μ` 施加的约束方向几乎相同。这是本实验的
   **经验**结果，**不是**定理。如果被截尾的比例更大，或者记录下限**远高于**真值 —— 即一个正的报告下限
   —— 就会出现偏差。另外注意截尾比例是**依赖预热的**（24 h 时 8 个点，120 h 时 10 个），而且会随时域
   延长继续增加，所以它不是设计的固定属性。
5. **报告方式（约半页）。** 把它作为一次稳健性检查陈述，并把修正量化：截断很罕见、集中在低残差的
   old 分区，且让 old 估计位移 −0.012 m/day，而不改变节点 15 的风险或风险排序。要说明**截尾似然正是
   本分析所使用的** —— 它是本次修订全程的主加权方式，不是一个附带检查 —— 并说明如果未来的数据集截断
   了多得多的点、或者使用一个正的报告下限，那么一个截尾感知的似然就会变得必要。

**论文草稿文本（约半页）—— 供 Step 11 使用：**

> *方法。* 由于合成观测被约束为非负，记录为零的观测被视为在所设边界处左截尾（`L = 0`）。正观测贡献
> 一个高斯密度项，而被截断为零的观测贡献累积概率 `P(Y* ≤ 0) = Φ(−μ(θ)/σ)`。这个 Tobit 型截尾高斯
> 似然与基线处理方式（把零观测按精确值录入）进行了比较。
>
> *结果。* 294 个预热后标定观测中有十个被截断为零 —— 节点 15 六个、节点 145 三个、节点 231 一个
> （全记录 1014 个中 43 个），所以截尾集中在、但不局限于低残差的 old 分区。在 30 组独立噪声实现上，
> 当截尾似然取代精确零处理时，old 组估计的中位数从 −1.0289 变为 −1.0405 m/day，而 average 组和 new 组
> 的估计不变；低氯汇总量和风险排序完全相同。
>
> *讨论。* 因此在本合成实验中，零下限处理对主要标定与风险结论的影响可以忽略，这反映了被截断观测数量
> 很少且它们出现在本已低残差的条件下。但如果被截尾观测的比例更大，或者仪器有一个正的报告下限，
> 截尾感知的似然就会变得重要。

## Step 10 —— 运行层面的风险指标（时长 + 深度）与水龄佐证

到目前为止，风险图被压缩成了单一的"低于**选定运行低氯阈值** `C_MIN = 0.2 mg/L` 的概率"（这是本研究
采用的一个代表性运行值，**不是**法定/合规安全限值）。单一概率把*多久*和*低多少*混为一谈。因此，从
按正式截尾似然加权的集合出发（非正式 GLUE 评分并列作为对照），我们报告：原概率被重新表达为一个时长、
**两个**真正的严重度指标（最低浓度、累积亏缺），以及**一个**与反应无关的水力诊断量（水龄）——
即*一个运行层面的重新表达 + 两个严重度指标 + 一个水力诊断量*，**不是**"三个新指标"
（`step10_risk_metrics.py`）。

**时间轴。** 预热后记录 `t = 120 … 168 h` 是 **49 个报告点、但 48 个一小时区间**。时长和亏缺是在这
**48 个区间上做梯形积分**（最大时长 48 h），不是在 49 个点上求和。

```
时长   D_i,n = ∫ 1[C<0.2] dt          （梯形，h；最大 48）  frac = D̄/48 ≈ 原来的 P(C<0.2)
亏缺   A_i,n = ∫ max(0, 0.2−C) dt      （梯形，mg/L·h）       ← 真正新增（严重度）
最低 C M_i,n = min_t C_i,n(t)          （先逐成员取最小，再加权 = 方法 A）← 真正新增
水龄        = EPANET AGE 运行（与反应无关；水力诊断量）
```

每个指标都是一个行为加权期望 `X̄_n = Σ_i w_i X_i,n`；5–95 % 带是加权集合分位数（**不确定性没有被
压缩掉**）。按期望累积亏缺排序：

| 节点 | E[时长] h [5–95] | E[亏缺] mg/L·h [5–95] | 最低 C 中位 [5–95] | 平均水龄 h |
| --- | --- | --- | --- | --- |
| 131 | **48.0 [48.0, 48.0]** | **4.22 [4.11, 4.32]** | 0.034 [0.03, 0.03] | 70.2 |
| 141 | 22.3 [20.0, 24.0] | 2.20 [2.08, 2.35] | 0.068 [0.06, 0.07] | 50.8 |
| 139 | 22.0 [22.0, 22.0] | 1.82 [1.73, 1.91] | 0.102 [0.10, 0.11] | 53.8 |
| 145 | 12.0 [12.0, 12.0] | 1.68 [1.62, 1.73] | 0.031 [0.03, 0.03] | 31.3 |
| 15 | 22.0 [22.0, 22.0] | 1.38 [1.16, 1.59] | 0.055 [0.05, 0.06] | 38.9 |
| 143 | 22.0 [22.0, 22.0] | 1.16 [0.95, 1.37] | 0.062 [0.06, 0.07] | 39.6 |
| 129 | 24.0 [24.0, 24.0] | 0.84 [0.80, 0.88] | 0.147 [0.15, 0.15] | 53.2 |

**水龄 ↔ 风险（全部 n = 92 个节点）：** 对时长的 Spearman ρ = 0.73，**描述性关联**
（空间分块 bootstrap 95% `[0.455, 0.897]`），对亏缺是 `0.72`；Pearson `0.86`。分块 bootstrap 重采样
10 个空间块（对标准化节点坐标做 k-means，2000 次重采样），所以它的宽度是**秩相关的保守描述性宽度，
不是显著性区间** —— 而且它大约是 iid 节点 bootstrap 所给宽度的两倍，这正是使用分块的意义。Spearman
是主统计量（风险指标是非线性的，而且很多节点是 0）。**普通 p 值是刻意不引用的**：92 个节点共享管段、
流径和水箱状态，它们远远不是 92 个独立样本。

**格局对推断约定的稳健性。** 两种加权给出的运行层面答案实质相同，这正是评审所问的问题：

| 方案 | ESS | 全网平均 E[D] (h) | 全网平均 E[A] | 与主分析前 10 名的重叠 |
| --- | --- | --- | --- | --- |
| 正式截尾（主） | 157 | 3.431 | 0.2181 | — |
| 非正式 GLUE | 4783 | 3.417 | 0.2207 | Jaccard 0.82 |

总体严重度在两种方案间相差 1.2%，十个热点节点中有九个是共享的（前 10 名 Jaccard 0.82；两份列表只在
节点 50 与节点 243 上不同）。不过节点身份**对预热的敏感度高于对加权的敏感度**：节点 243 此前按亏缺
排名最差，在修正后的 120 h 预热下**完全跌出前十**。

**用哪一种全网平均？** 对 92 个节点做不加权平均，会把一个零需求节点和最大用户同等看待。92 个节点中
有 59 个带非零需求，合计 **690.7 L/s**，所以这个选择是有影响的，因此三种都报告，而不是默默取一种：

| 指标 | 不加权（全部 92） | 仅用户（59） | 需求加权 |
| --- | --- | --- | --- |
| `E[D]` (h) | 3.4309 | **4.4610** | **1.2311** |
| `E[A]` (mg/L·h) | 0.2181 | 0.3053 | 0.0798 |
| 最低 C (mg/L) | 0.4922 | 0.4412 | 0.6348 |

**需求权重是 pattern 感知的，而且必须如此。** 权重来自
`wntr.metrics.hydraulic.average_expected_demand`，它会应用每个节点的 pattern 和全局需求乘子；全网合计
是 **690.7 L/s**。本日志的早先版本读的是原始 `base_demand` 字段，那个被取代的读法值得记录，因为它
失败得非常安静：Net3 有四个节点（15、35、123、203）把一个很大的需求写成 1 GPM 乘以一个很大的 pattern，
所以只看 base 字段会把它们各报告为 0.063 L/s，而不是 16.7 / 108.4 / 75.3 / 284.6 —— 合起来是
**全网实际水量的 70%，却被当成四个最小的用户** —— 并给出 192.6 L/s 的全网合计。下面每一个需求加权
数字、以及 Step 12 里每一个 L/s，在修正后都变了。

这两种调整**方向相反**，而其原因本身就是一项结果：仅用户平均比不加权*更差*（4.46 对 3.43 h），而需求
加权则*更好*（1.23 h）。这种组合只可能在风险集中于**小**用户而非大用户时出现 —— 也就是管网末梢和低
周转的死端，那正是预期停留时间长的地方。所以最差的氯条件与最少的需求重合，而且 pattern 修正**强化**
了这一点：一旦那四个大 pattern 需求按真实规模计入，需求加权的严重度就从 2.36 h 降到 1.23 h，即大用户
相对全网平均而言，比只看 base 的读法所显示的**服务得更好**。

这对报告有两个后果。本日志别处使用的不加权数字是**保守**选择，而不是好看的选择 —— 需求加权会把每一个
严重度数字砍掉一半以上。而一个需求加权的头条数字会恰好低估风险图本该找出来的那些用户，所以在给出任何
需求加权数字时，都应当同时引用仅用户平均。

**小时级报告会漏掉短时偏离吗？** 水质求解器以 300 s 步进，但风险指标积分的是**小时**报告，所以一次
在同一小时内开始又结束的下探是不可见的，而且对二值示性函数做梯形积分会把任何穿越点放在两个报告点的
中点上。权重最高的 12 个成员在三种报告分辨率下重跑：

| 报告步长 | 窗口内点数 | 全网平均 `E[D]` (h) | 全网平均 `E[A]` | 与小时级的前 10 名 Jaccard |
| --- | --- | --- | --- | --- |
| 3600 s | 49 | 3.436 | 0.2180 | 1.00 |
| 900 s | 193 | 3.374 | 0.2159 | 1.00 |
| 300 s | 577 | 3.380 | 0.2164 | 1.00 |

从小时级换到求解器自身的 300 s，`E[D]` 变化 **−1.6%**，`E[A]` 变化 **−0.7%**，而且前 10 名集合完全
相同。有两点值得注意。变化是**负的**，所以小时级报告是轻微*高估*时长，而不是漏掉偏离 —— 梯形积分对
穿越点的抹平效应超过了任何在报告点之间丢失的下探。而且大部分变化在 900 s 就出现了，到 300 s 不再继续，
这正是收敛的样子。**因此小时级报告在这里是足够的**，而且它足够的原因是本网络中氯浓度场在小时尺度上是
光滑的，不是因为亚小时行为被假设掉了。

与水龄相关的风险；前几名节点的期望时长及 5–95% 带

结论：

1. **时长和深度在一个大体重叠的热点簇内部给出不同的排序。** 节点 **131** 在两个口径上都是最差的
   （整整 48 h 低于 0.2，*而且*亏缺最大，4.22 mg/L·h），但在它之下两个指标就分歧了：**145** 是
   *深而短*的风险（最低 C 0.031，但只有 12 h），而 **129** 是*长而浅*的（24 h，最低 C 0.147，表中亏缺
   最小）。簇 {131, 141, 139, 145, 15, 143, 129, 253} 在各指标间大体重叠而内部次序改变，这正是分开报告
   时长和深度的意义。
2. **集合不确定性比非正式评分下窄得多。** 在正式加权下，5–95 % 带塌缩到此前宽度的一小部分
   （节点 15：22.0 [22.0, 22.0] h，而非正式集合给出的是 14–24 h）。这与参数上看到的是同一种效率增益，
   传播到了风险指标上：**早先的宽带主要是加权方式的惯性，不是不可约减的参数不确定性。**
3. **水龄为空间格局提供了水力上的佐证。** 平均水龄与时长和亏缺都强*关联*（Spearman 0.73，n = 92，
   空间分块 bootstrap [0.455, 0.897]）；最差的节点也有最长的停留时间。这是**佐证，不是验证**：水龄来自
   *同一个*水力模型（不是独立测量），相关不等于因果，而且余氯还取决于壁面衰减、源头投加和水箱混合。
4. **水龄的量级依赖窗口，不是稳态。** 水龄在 168 h 模拟内仍**依赖时域**：高水龄节点的场在整个运行期间
   都还在填充。上表中的水龄是固定 **120–168 h** 评估窗口上的均值，**绝不能解释为稳态水龄** —— 同样这些
   节点在"最后一个昼夜周期（144–168 h）"和"最后一小时（`t = 168 h`）"两种定义下给出的数字不同。三种
   定义都存在 `step10_risk_metrics.json` 的 `age_windows` 下，所以这个选择永远是显式的而非隐含的。
   **Step 0 解决了这里过去悬而未决的问题：跑得更久也解决不了。** 水龄场的周期间变化在 120–144 h 预热
   处仍有 12.8 h，且每周期只衰减约 12%，所以穿越点外推到约 600 h —— 远超模型允许的 168 h。因此 Net3 的
   绝对水龄**按构造就是依赖时域的**，而不只是在这里欠收敛。**与氯风险的秩关联才是相关的结果；绝对量级
   仍对所选时域敏感** —— 这就是为什么本节作为结论报告的是 Spearman，而不是绝对水龄。
5. **谨慎表述的解释 —— 稳健性取决于扰动的种类，也取决于决策尺度。** 主导的衰减项（old）在扩展的现实性
   分析下是*最稳健被告知*的系数（Steps 4/7），而水龄与反应无关，所以领先的热点由停留时间和 old 组衰减
   支配，而不是由被弱告知的 avg/new 系数支配。但这买到的东西比本段早先版本所声称的少：

   - **稳健。** 广义的风险格局在正式与非正式加权方案之间基本不变（全网平均 `E[A]` 相差 1.2%，十个热点
     中共享九个），而且它在测试过的每一种单传感器偏置下都保持强秩相关 —— Step 8c 全部 24 个分支
     Spearman ≥ 0.999，且在每一个负偏移下前 6 名集合完整。
   - **依赖度量，而且本表的度量是较温和的那个。** 把 `k_b` 固定在偏离真值 20% 的位置，会改变
     **时间平均概率 `P_bar`** 上的领先集合 —— 两个符号下前 6 名 Jaccard 都是 0.50，前 3 名 0.20，基准
     第 4 名跌到第 20。**在上表所用的累积亏缺 `E[A]` 上，它的作用小得多**：`k_b = −0.4` 时前 6 名
     *不变*，`−0.6` 时以一次第六/第七名交换（143 出、129 进）丢掉一个节点，前 3 和前 5 完全相同
     （Step 8b 结论 4–5）。

   可辩护的总结是：*参数不确定性影响节点级风险指标的**量级**（见 5–95% 带）；广义空间格局对加权方案和
   单传感器偏置是稳健的；本节报告的按亏缺排序的候选名单对 `k_b` ±20% 稳健，只有一次边界交换；而按时长
   排序的候选名单不稳健。* 我们**不**声称不确定性"没有传播" —— 它传播了，传播到了量级上 —— 而且在本
   项目中，任何关于"热点排序"稳定性的陈述，**不点名它所依据的度量就没有意义**。

## Step 11 —— 留一监测点（LOO）预测验证

草稿在同样的六个监测点上标定并评估，没有任何样本外检查。LOO 交叉验证填补了这个空缺：留出一个监测点，
在其余五个上对缓存集合重新加权，然后 (a) 检查三个 k_w 是否稳定，(b) *预测*那个被留出的传感器并测量
样本外误差和预测带覆盖率（`step11_loo.py`；复用缓存，30 次噪声实现）。两种加权都跑；**正式截尾似然是
主分析**，非正式 GLUE 评分（阈值按 5 个监测点的 σ 缩放）是对照。全六点基准：
正式 old −1.0405 / avg −0.1028 / new −0.0509；非正式 old −1.0382 / avg −0.1171 / new −0.0516。

```
留出点预测 RMSE  = √[ mean_t (pred_mean_m(t) − obs_m(t))² ]     与噪声底 σ = 0.1 比较
90% 预测带       = pred_mean ± 1.645·√(Var_集合 + σ²)            （参数 + 观测噪声）
覆盖率           = 留出小时数中落在 90% 带内的比例
```

**主分析 —— 正式截尾似然：**

| --- | --- | --- | --- | --- | --- |
| 107 (new) | -1.038 | -0.104 | -0.050 | 0.098 | 0.92 |
| 113 (new) | -1.031 | -0.098 | -0.053 | 0.103 | 0.90 |
| **15 (old)** | **-1.086** | -0.102 | -0.050 | 0.094 | 0.94 |
| 145 (old) | -1.060 | -0.102 | -0.051 | 0.092 | 0.94 |
| 209 (average) | -1.040 | -0.102 | -0.050 | 0.099 | 0.91 |
| 231 (average) | -1.045 | -0.106 | -0.051 | 0.099 | 0.92 |

**对照 —— 非正式 GLUE：**

| 留出点（分区） | k_old | k_avg | k_new | 该点预测 RMSE | 90% 覆盖率 |
| --- | --- | --- | --- | --- | --- |
| 107 (new) | -1.040 | -0.116 | -0.051 | 0.097 | 0.92 |
| 113 (new) | -1.036 | -0.116 | -0.052 | 0.102 | 0.90 |
| **15 (old)** | **-0.985** | -0.115 | -0.053 | 0.095 | 0.94 |
| 145 (old) | -1.025 | -0.117 | -0.051 | 0.091 | 0.94 |
| 209 (average) | -1.037 | -0.119 | -0.053 | 0.099 | 0.92 |

LOO 样本外预测误差 ≈ 噪声底；被留出的节点 15 的带覆盖了数据

结论：

1. **样本外预测处在噪声底上。** 在**正式主规则**下，每个被留出的监测点的预测 RMSE 都是
   **0.092–0.103** mg/L ≈ σ = 0.1（非正式对照 0.091–0.102）—— 也就是说，五监测点标定对那个*未见过*的
   传感器的预测精度，大致就是测量噪声所允许的极限。**没有过拟合的迹象；模型在空间上是可泛化的。**
   两种加权在这里一致，考虑到它们经常不一致，这值得一提：**预测**是非正式评分做得同样好的那件事，
   因为它并没有被要求去提取参数信息。
2. **不确定性接近名义值，说"保守"是夸大了。** 90 % 预测带（参数 + 观测噪声方差）覆盖了留出小时数的
   **0.90–0.94**，两种规则下都是。平均值略高于名义值，但最小值**恰好**是 0.90（监测点 113），所以这个
   带是**校准良好**而不是系统性保守 —— 真正保守的情形是 Step 11c 的未监测节点，它们过覆盖到 1.00。
3. **参数稳定性确认了信息所在的位置 —— 但两种加权在符号上分歧，而主分析才是该引用的那个。** 在两种
   规则下，`k_old` 都只在**移除一个 old 分区监测点时**才有可察觉的移动，而在移除 new/avg 监测点时几乎
   不动，这正是 Fisher 和剖面所预测的：old 的信息位于监测点 15/145。但*方向*不同。在**正式主规则**下，
   移除节点 15 把 `k_old` 从 −1.0405 移到 **−1.086**，移除 145 移到 −1.060 —— 即衰减*更强*，**背离**
   真值 −1.0。在非正式对照下，同样的移除给出 **−0.985** 和 −1.025 —— 衰减*更弱*，**朝向**真值。量级
   相近（约 0.05）但符号相反，所以"移除节点 15 会把 old 拉向 −0.99"这样的句子**只对对照组成立**。

   **`k_avg` 和 `k_new` 在两种规则下也都稳定 —— 但原因不同，而且正式那种绝不能被描述成先验主导。**
   在非正式对照下，它们确实是先验主导的：它们保留了 92% 和 88% 的先验宽度（Step 3），所以本来就没有
   多少东西可供一个被移除的监测点去改变。在**正式主规则下它们是被告知的** —— 保留了 30.7% 和 28.3% 的
   先验宽度（Step 1），而且它们的集合 SD 落在 Case-A CRLB 的百分之几以内（Step 7）。它们在这里的稳定性
   有另一个原因：**留一监测点总是把同分区的搭档监测点留在标定集里**，所以没有任何分区变成未观测，
   每个系数都保留了自己的信息来源。把这称为先验主导会与本项目的核心正式结果相矛盾。**一个分区的信息
   真正丢失时会发生什么，只有在下面更难的留一分区实验里才看得到** —— 那里一个分区的两个监测点都被移除，
   而该系数确实退回了先验。
4. **但这是简单情形，单靠它并不支持当初要求它支持的那个论断。** 每个被留出的监测点在同一分区都有一个
   搭档，所以该分区仍被观测。因此加了两个更难的检验。

### Step 11b —— 留一**分区**：一个分区变成完全未观测时会怎样

一个分区的两个监测点都被丢弃，所以标定只有四个监测点，而且有一个分区完全没有传感器。**这才是真正回应
那个论断的检验。**

两种加权都跑：非正式是为了与 Step 11a 衔接，正式是为了让下面的非均质真值检验与本检验*只*在真值上不同。

| 方案 | 丢弃分区 | 监测点 | `k_w,old` | `k_w,avg` | `k_w,new` | 自身系数误差 | 自身 SD 保留 | 预测 RMSE | 90% 覆盖 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 非正式 | old | 15, 145 | **−0.850** | −0.115 | −0.052 | **+0.150** | **100%** | 0.100 | 0.96 |
| 非正式 | average | 209, 231 | −1.045 | **−0.120** | −0.054 | **−0.020** | **100%** | 0.099 | 0.93 |
| 非正式 | new | 107, 113 | −1.035 | −0.116 | **−0.052** | −0.002 | 95% | 0.100 | 0.92 |
| 正式 | old | 15, 145 | **−0.851** | −0.102 | −0.051 | **+0.149** | **100%** | 0.100 | 0.96 |
| 正式 | average | 209, 231 | −1.038 | **−0.120** | −0.050 | **−0.020** | **100%** | 0.099 | 0.92 |
| 正式 | new | 107, 113 | −1.049 | −0.101 | **−0.049** | +0.001 | **57%** | 0.101 | 0.90 |

**结论，而且它改变了 LOO 结果的价值。** 移除一个分区的两个监测点，该分区的系数就**退回它的先验中点**
—— `old` 退到 −0.850（先验中点 −0.850），保留 100% 的先验宽度；`average` 退到 −0.120（先验中点 −0.120），
同样 100%。两种加权下都如此。所以对这两个分区而言，**每个系数只被它自己的两个监测点告知，别无来源**。

`new` 是例外，而且很有启发：在正式似然下，即便它的两个监测点都没了，它仍保留 **57%** 的先验宽度，
说明确实有一些关于它的信息来自别处。这与 Step 7 的 Jacobian 吻合，那里 `new` 在*每一个*监测点上都有
最大的单位敏感度（2.12 对 `old` 的 0.19 mg/L per m/day），因为 new 分区的管段位于整个网络的上游。
**空间借用是存在的，但只对水最先流经的那个分区。**

决定性的观察是右边那两列：**预测质量没有变化**。留出点 RMSE 仍约 0.10 mg/L，覆盖率仍是 0.90–0.96
（正式；非正式 0.92–0.96），即使对那个系数带着 +0.150 误差、什么都没学到的分区也是如此。所以
**预测成功不是参数可辨识性的证据**，Step 11a 的 LOO 结果**不能**被读作对系数的验证。预测之所以能成功，
是因为先验本来就以真值为中心 —— 正是评审在 §3.1 指出的那个产物 —— 所以先验均值的预测本来就已经很好。
**§3.1 的问题和 §4-#6 的验证是同一个问题被看到了两次。**

### Step 11c —— 从未进入任何标定的节点

20 个未监测节点（种子 7），对照**无噪声真值**进行预测。带的构造与 Step 11a **刻意不同**：预测一个真值
只需要参数离散度，不需要测量噪声项，因为那里没有传感器来添加噪声。

| 加权 | 90% 覆盖率（正态近似） | 90% 覆盖率（加权分位数） | 平均 \|预测 − 真值\| / 平均\|真值\| |
| --- | --- | --- | --- |
| 非正式 GLUE | 1.00 | 1.00 | 0.006 |
| 正式截尾 | 1.00 | 1.00 | 0.008 |

名义覆盖率是 0.90，所以两种方案都**过覆盖**：这些带是保守的而非校准的。未监测节点上的平均预测误差是
当地浓度的 0.6–0.8%。之所以在正态近似之外还并列报告加权分位数带，是因为集合是偏斜的且在零处被截尾，
而在这种情况下对称带在真正要紧的那个方向上并不保守；这里两者一致，所以在这些节点上正态近似是够用的。

### Step 11d —— 最难的情形：非均质真值上的留一分区

检验 a–c 用的真值都由随后被拟合的那个三分区模型生成，所以不可能出现结构性差异。这里真值带有 ±20% 的
逐管非均质性（Step 5c 的设计，8 个独立场）**并且**有一个分区未被观测，所以外推和结构误差被**同时**
检验 —— 这正是风险图实际依赖的组合。使用正式加权，所以它与 Step 11b 的正式行之间*只*差一个真值。系数
误差是相对每个场自己的算术分区均值度量的，所以它不会被非均质性本身放大。

| 丢弃分区 | 自身系数误差 | 自身 SD 保留 | 预测 RMSE | 90% 覆盖 | 未监测点相对误差 |
| --- | --- | --- | --- | --- | --- |
| old | +0.139 | 100% | 0.098 | 0.96 | 0.008 |
| average | −0.020 | 100% | 0.097 | 0.94 | 0.012 |
| new | +0.012 | 55% | 0.102 | 0.88 | 0.011 |

**结构性差异在"丢失传感器"之上几乎没有增加任何东西。** 逐行与 Step 11b 的正式行对比：系数误差
+0.139 / −0.020 / +0.012 对 +0.149 / −0.020 / +0.001，SD 保留 100 / 100 / 55% 对 100 / 100 / 57%，
预测 RMSE 和覆盖率相差在 0.005 和 0.02 以内。未监测节点上的预测仍保持 0.8–1.2% 的相对误差。所以在本
网络、本噪声水平下，**一个未观测分区的代价远远超过 ±20% 分区内结构误差的代价** —— 这与 Step 5c 一致，
那里同样的非均质性在 25 个场上没有产生可检出的偏差。

有一个数字确实朝着值得注意的方向移动了：被丢弃的 `new` 分区的覆盖率降到 0.88，刚好低于名义的 0.90，
是这些检验中唯一一个低于名义值的数字。它恰好是同时具有结构性差异和部分被告知系数的那个情形，也就是
预测带最应该先失去校准的地方。

**这四项检验合起来确立了什么、没确立什么。** 它们确立了**内部一致性**，而且精确地界定了这种一致性的
边界：被标定的集合能在噪声底水平上复现未见过的监测点，能以约 1% 的误差复现未见过的节点，预测带是保守
的，而且在 ±20% 的结构误差下依然如此。它们**没有**确立**外部有效性** —— 真值始终是模型生成的 ——
而且 Step 11b 表明它们甚至没有确立系数是被告知的，因为在一个系数停留在其先验上的同时预测依然成功。
诚实的总结是：**空间预测和参数辨识在这里是两个各自独立的论断，而只有第一个是被支持的。**

## Step 12 —— 运行层面的温度 / 老化情景投影（供水安全计划应用）

**角色。** 在标定（Steps 1–9）、基线风险指标（Step 10）和 LOO 验证（Step 11）之后，本节回答导师提出的
运行层面问题：*给定被标定的集合，在暖季和热浪条件叠加老化反应性胁迫下，全网低氯风险会怎样，以及提高
源头投加量能否恢复基线状态？* 导师是以 GLUE 集合的说法提出的，因为草稿只有那个；而这里传播的集合是按
**正式截尾似然**加权的，所以下文不用 GLUE 这个词来称呼它。

这**不是**对随附的均质 `k_w` notebook 的重跑。情景*方法*（Arrhenius 缩放 → 集合传播 → 可能性×后果 →
风险登记表 → 投加评估）被移植到**本**项目六监测点、三分区、**正式加权**的集合上（`k_b = −0.5` 固定；
正式截尾权重，ESS 157）。8192 个抽样中有 2196 个被带入后续：权重超过最大权重 `1e-6` 的那些。这是一个
**为控制情景运行成本而做的数值截断，不是行为阈值** —— 正式似然没有接受截断。这个代价现在是被记录而非
断言的：被丢弃的 5996 个抽样的权重合计为 **3.79 × 10⁻⁶**，所以保留下来的集合占总权重的 0.9999962，
比本节报告的任何数字的分辨率都低若干个数量级（artifact 中的 `discarded_weight_mass`）。**导师的数字与
这些不可比，绝不能作为本研究的结果引用。**

### 12.1 两种概率定义 —— 务必区分

Step 10 报告的是*时间平均*概率；Step 12 的头条是*窗口破限*概率。它们回答不同的问题，两者都报告。

**公式**：

```
P_min(s,n) = Σᵢ wᵢ · 1[ min over t ∈ [120, 168] h of C(s,i,n,t) < C_crit ]
P_bar(s,n) = E[D(s,n)] / 48                     （Step 10 的那个量）
E[D(s,n)]  = Σᵢ wᵢ · ∫ 1[C < C_crit] dt          （h，48 个区间上的梯形积分）
E[A(s,n)]  = Σᵢ wᵢ · ∫ max(0, C_crit − C) dt     （mg/L·h）
```

**性质**：

- `P_min` = 节点在窗口内**至少破限一次**低于 `0.2 mg/L` 的概率；`P_bar` = 随机抽取的某一小时低于它的
  概率。恒有 `P_min ≥ P_bar`。
- 窗口是 **48 h**（`t = 120…168`，预热后），所以 `P_min` 是一个 48 小时窗口的最小值，**不是** 24 小时的
  "日最小值"。对于其余条件相同的轨迹，48 小时窗口破限概率**不可能低于**其内嵌 24 小时窗口上的相应概率，
  且在昼夜模式重复时两者**相等**。因此窗口长度只是不与导师数字比较的次要理由；**主要理由**是参数化、
  监测阵列、集合和模拟设置都不同。
- "`P_min > 0.5` 节点数"在全部 92 个节点上统计；"不确定"是 `0.05 < P_min < 0.95`；"风险需求量"是对
  `P_min > 0.5` 的节点求基本需求之和（零需求节点贡献 0）；`E[D]` / `E[A]` 的"全网平均"是**对全部 92 个
  节点的不加权算术平均**，单位分别是 `h` 和 `mg/L·h`。

### 12.2 情景构造

三种情景不确定性用**共同随机数**联合传播 —— 每个行为成员抽取一组 `(E_a,bulk, E_a,wall, δT)`，并在
每个情景、每个投加量下复用 —— 所以情景之间的差异是物理的，不是蒙特卡洛噪声。

**公式**：

```
T(s,i)       = T_mean(s) + δTᵢ,          δTᵢ ~ N(0, 1²) °C
f(T, Ea)     = exp[ −(Ea/R) · (1/T − 1/T_ref) ],   T 用 K
k_b,i(s)     = (−0.5) · f(T(s,i), E_a,b,i)
k_w,g,i(s)   = k_w,g,i(T_ref) · f(T(s,i), E_a,w,i) · α_g(s),   g ∈ {old, average, new}
```

其中 `E_a,bulk ~ N(45, 8²)` kJ/mol，`E_a,wall ~ N(35, 10²)` kJ/mol，两者都在 **5 kJ/mol 处下截断**
（从截断正态中抽样而非事后裁剪，所以不会有非物理的抽样，也不会有概率质量堆在边界上）。脚本对此做了断言：
实际抽样范围为 `17.59–72.05`（体相）和 `5.10–70.24` kJ/mol（壁面），全部高于 5 kJ/mol 的界。水温偏移
现在也做了截断，到 `±4.0 °C`，这恰好是使每个情景均值都留在所声明的 `8–24 °C` 有效范围内的区间；实际
温度范围为 `8.48–23.50 °C`，没有任何抽样需要重抽。所有这些都记录在 `step12_scenarios.json` 里而不只是
打印出来，所以可以被核查。

| 键 | 标签 | 平均水温 | 老化乘子 `α` |
| --- | --- | --- | --- |
| A | 基线 12 °C | 12 °C | 全部 1.00 |
| B | 暖季 16 °C | 16 °C | 全部 1.00 |
| C | 热浪 20 °C | 20 °C | 全部 1.00 |
| D | 热浪 + 老化胁迫 | 20 °C | new 1.00 / avg 1.35 / old 1.85 |

**论文中需要声明的假设**：

- 被标定的系数是**在一个示意性参考温度下的有效参数**，`T_ref = 12 °C`；这是从导师材料继承的，
  **不是**从 Net3 测量出来的。
- 老化乘子是**只升不降的胁迫测试输入**（`α ≥ 1`），不是资产记录。因为基线模型已经区分了 new/average/old
  的 `k_w`，所以不使用 `α_new < 1` —— 那会削弱本已很弱的新管，并重复计入分区结构。因此情景 D 被命名为
  *老化反应性胁迫*，而不是"老化的影响"。
- `C_crit = 0.2 mg/L` 和基于需求的后果三分位点（`1.67`、`4.38 L/s`）是示意性的运行输入，不是法定限值。
  需求是**后果的代理量**，不是人口或暴露量。

**数值保护（重要）。** 分区 `k_w` 被裁剪到 `CLIP_LO = −8.0 m/day`，纯粹作为求解器保护。早先的一次运行
用的是 `−3.0`，它在**情景 D 中对 46.8 % 的成员是激活的**（先验下界 `−1.5` × `f_w ≈ 1.5` × `α_old = 1.85`
达到 `−5.3`），**悄悄地让所报告的均值产生了偏差**。现在这个保护是失活的：脚本断言**每个情景中被裁剪的
抽样数为 0**，并验证

```
mean k_w,old(D) / mean k_w,old(C) = 1.8500 = α_old      （精确到 1e-6）
```

**今后任何对先验或 `α` 的改动都必须重新检查这条断言。**

**这有两个不同的成因，本日志的早先版本把它们混为一谈了。**

1. **饱和。** 一个已经处于 `very high` 的节点无法再上升，所以 `max(破限, 严重度)` 没有上升空间。主导
   规则决定的是*哪个轴驱动一次行动*；它并不能让一次等级比较对天花板处的变化变得敏感。这是两个独立的
   性质，而当初只论证了第一个。
2. **乘法矩阵的天花板。** `得分 = 轴得分 (1–5) × 后果得分 (0–3)`，所以一个**次要**用户（后果 1）最高
   只能到 5 分 → `medium`，无论它遭遇什么。**有 20 个节点（17.46 L/s）按构造被封顶在 `high` 以下。**
   这个登记表根本无法把"这个小用户整整一个窗口都没有氯"表达成比 medium 更严重的东西。**这是
   `可能性 × 后果` 这种形式本身的性质，不是本实现的问题。**

所以等级变化那几列是**必要但不充分的**。对任何等级无法移动的节点，升级必须在连续指标（`ΔE[D]`、
`ΔE[A]`）上读，这也是为什么它们被保留在 artifact 里。

**这个得分是什么、不是什么。** 它的可能性轴是 `P_min` —— 48 h 窗口内*任何一次*破限的概率 —— 所以这个
乘积衡量的是**节点是否会破限，按它服务的水量加权**。单独看它会把"整个窗口都只略低于阈值"和"远低于
阈值但只有两小时"混为一谈：一个只在某一刻略微跌破 0.2 mg/L 的节点，和一个在 0.03 mg/L 上待满 48 h 的
节点，会得到相同的可能性等级。它是一个**破限概率 × 后果**的乘积，在登记表中命名为 `risk_score_breach`。

### 12.5.1 第二条并行轴：严重度

因此登记表在**同一后果轴上**携带**第二个乘积**，衡量的是*多久*而不是*是否*：

| 严重度等级 | 按 `E[D]`（48 h 窗口内低于 0.2 mg/L 的小时数） | 得分 |
| --- | --- | --- |
| negligible（可忽略） | `E[D] < 1` | 1 |
| brief（短暂） | `1 ≤ E[D] < 6` | 2 |
| sustained（持续） | `6 ≤ E[D] < 12` | 3 |
| prolonged（长时） | `12 ≤ E[D] < 24` | 4 |
| persistent（持久） | `E[D] ≥ 24`（窗口的一半或更多） | 5 |

`risk_score_severity = 严重度得分 × 后果得分`，范围同样是 `0–15`，映射规则相同，所以两个乘积直接可比。

有三个选择需要说明。**这些分界是事先声明的绝对小时数，不是本网络自身结果的分位数** —— 一个从数据里取
出来的尺度会随热浪一起移动，因此永远无法显示升级。**用 `E[D]` 而不是 `E[A]` 作为轴**，是因为"低于阈值
多少小时"具有运行意义，而一个 `mg/L·h` 的积分没有。而由于 `E[D]` 本身无法区分"长而浅"和"短而深"，
登记表还携带 `E_depth_while_below_mgL = E[A]/E[D]`，即处于阈值以下时低于阈值的平均深度。

**两条轴不是独立的 —— 但这个约束比看上去弱，本节的早先版本夸大了它。** 由于
`D_i ≤ T_window · 1[成员 i 破限]`，取加权期望得到

```
E[D] ≤ T_window · P_min        等价地   P_bar ≤ P_min
```

在登记表上验证：**92 个节点中有 0 个违反它**，而最紧的那个节点达到
`E[D] / (T_window · P_min) = 0.97`。

本节此前把这读作"因此严重度得分永远不可能超过可能性得分，所以分歧必然是单向的"。**那是错的。** 这个
不等式约束的是*连续*量；而两个得分是在**不同且未对齐的尺度**上分档的，所以这个界限**限制**了一次反转
的幅度，却**没有禁止**它。一个位于界限内部的反例：

```
P_min = 0.03,  E[D] = 1.2 h        1.2 ≤ 48 × 0.03 = 1.44  ✓ 满足界限
                                   可能性等级 1（P < 0.05）
                                   严重度等级 2（E[D] ≥ 1 h）      -> 严重度更高
```

这个界限真正买到的，是对反转**幅度的限制**，而且是在代码里从各分界自身推导出来的（不是断言的），
所以即便将来改动任一尺度它仍然成立：

| 可能性等级 | `P_min` 上确界 | ⇒ `E[D]` 上确界 | 可达到的最高严重度等级 | 最大反转 |
| --- | --- | --- | --- | --- |
| 1 | 0.05 | 2.4 h | 2 | **+1** |
| 2 | 0.20 | 9.6 h | 3 | **+1** |
| 3 | 0.50 | 24.0 h | 4 | **+1** |
| 4 | 0.80 | 38.4 h | 5 | **+1** |
| 5 | 1.00 | 48.0 h | 5 | 0 |

所以严重度**最多**只能比可能性高一个等级，而且一旦 `P_min ≥ 0.80` 就完全不能超过。因此下面关于所观察到
的分歧方向的一切，都是关于**本场的经验陈述**，不是那个不等式的推论。

**而且经验上离反转很近。** 对每个用户节点度量"它的 `E[D]` 还要增加多少，严重度得分才会超过可能性得分"：
最近的是 **0.939 h** —— 在一个 48 h 窗口里，不到一小时的额外低于阈值时间。59 个用户中有十七个的 `P_min`
高到永远不可能反转，但其余的**并没有任何结构性的保护**。"这里没有反转"是一个关于本场的事实，余量大约
一小时，**它绝不该被写成一条定理**。

**为什么时长分界没有与概率分界对齐。** 把它们设成 `2.4 / 9.6 / 24 / 38.4 h` —— 即概率分界乘以窗口长度
—— 会让次序得到保证。这被否决有两个理由。它会摧毁严重度等级的运行意义，而那正是选择 `E[D]` 而非 `E[A]`
的全部理由；而且它会让这个次序变成*尺度*的性质，而不是关于网络的一项发现。**一条按构造就无法在某个
方向上产生分歧的第二轴是更弱的工具**，那时"严重度从不超过破限"就会是同义反复而不是结果。

**结果（情景 A，59 个用户节点）。** 严重度等级：negligible 42，brief 1，sustained 6，prolonged 9，
persistent 1。与破限乘积对比：**49 个处于相同风险等级，10 个处于更低等级，0 个处于更高等级。**

**四个情景都做了分档，这正是绝对分界发挥价值的地方。** 严重度尺度之所以用绝对小时数声明，正是为了能
跨情景携带；这种可携带性现在是被**实际检验**的，而不只是被声称的（`E[D]` 在每个情景下本来就已算出，
所以不需要额外模拟）：

| 情景 | negligible | brief | sustained | prolonged | **persistent** | 高/极高（破限） | 高/极高（严重度） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A. 12 °C | 42 | 1 | 6 | 9 | **1** | 10 | 6 |
| B. 16 °C | 38 | 5 | 6 | 6 | **4** | 12 | 6 |
| C. 20 °C | 36 | 3 | 8 | 6 | **6** | 13 | 7 |
| D. 20 °C + 老化 | 35 | 4 | 6 | 6 | **8** | 13 | 7 |

**两条轴的升级方式不同，而持续移动的是严重度轴。** *persistent* 用户的数量 —— 至少半个窗口低于
0.2 mg/L —— 从 **1 → 4 → 6 → 8** 单调增长且没有走平。破限计数则是 10 → 12 → 13 → **13**，在 C 和 D
之间**饱和**：在 20 °C 时暴露集合中的大部分已经处于 `P_min > 0.8`，所以再加老化胁迫也推不动它。严重度
轴上的风险需求量（sustained 及以上）走的是 50.6 → 50.6 → 60.0 → 60.0 L/s。

这是本日志中支持保留第二条轴的最强论据：**情景 D 中的老化胁迫对破限乘积几乎不可见，对严重度乘积则清晰
可见。** 一个只建立在破限概率上的登记表会报告"在热浪之上老化几乎没有增加什么"，而那不是这个场实际
发生的事。

那十个节点共有的是*概率*和*时长*：`P_min = 1.000`（节点 125 为 0.998），`E[D]` 在 48 h 中占 2.0–17.9 h。
它们**不**共有的是深度，而本节的早先版本错误地把它们压平成了"只是略低于阈值"。按深度排序：

| 节点 | `P_min` | `E[D]` (h) | 低于阈值时的深度 (mg/L) | 低于阈值时的平均 C | `E[A]` (mg/L·h) | 需求 (L/s) | 破限等级 | 严重度等级 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 145 | 1.000 | 12.02 | **0.1400** | **0.0600** | **1.6826** | 1.86 | very high | high |
| 251 | 1.000 | 6.00 | 0.0954 | 0.1046 | 0.5727 | 1.63 | medium | low |
| 253 | 1.000 | 8.00 | 0.0947 | 0.1053 | 0.7577 | 3.68 | very high | medium |
| 247 | 1.000 | 2.00 | 0.0899 | 0.1101 | 0.1799 | 4.75 | very high | medium |
| 255 | 1.000 | 8.00 | 0.0880 | 0.1120 | 0.7039 | 2.73 | very high | medium |
| 147 | 1.000 | 7.45 | 0.0793 | 0.1207 | 0.5906 | 0.58 | medium | low |
| 149 | 1.000 | 6.04 | 0.0487 | 0.1513 | 0.2942 | 1.83 | very high | medium |
| 151 | 1.000 | 7.48 | 0.0423 | 0.1577 | 0.3164 | 9.75 | very high | high |

**深度跨越 5.51 倍，绝不能被总结成"浅"。** 一端是节点 125，它在低于阈值时平均为 `0.1746 mg/L` ——
确实是边缘情况。另一端，**节点 145 在低于阈值时平均为 `0.0600 mg/L`，不到阈值的三分之一**。把两者都叫
"略低于阈值"，正是严重度轴被引入来阻止的那种压平，只不过发生在低一层。

**而且严重度等级把它藏起来了。** 节点 125、145 和 153 都属于 *prolonged*（`E[D]` 12–24 h），但它们的
累积亏缺分别是 `0.4343`、`1.6826` 和 `0.6567 mg/L·h` —— **在同一个等级内部相差 3.9 倍**。这是 `E[D]`
的盲区，§12.5.1 把它作为设置深度列的理由陈述过，现在在真实节点上被演示了：等级回答的是"多久"，只有
深度那一列才回答"低多少"。**一个严重度等级绝不能被单独读作关于量级的陈述。**

所以对这十个节点的诚实总结是：它们几乎必然会在窗口的一部分时间内破限，而它们的平均破限深度差异显著，
从 `0.025` 到 `0.14 mg/L`。在破限乘积上，它们与节点 131 无法区分，而后者在 48 h 中有 **46.6 h** 低于
阈值；严重度乘积按时长把它们分开，深度那一列再把它们分开一次。

**这一对该怎么读。** 在本场中，破限乘积从不*低估*严重度，而对 59 个用户节点中的 10 个**高估**了它。
两种次序都不是"正确"的那个：`P_min` 是回答"这个节点是否合规"的正确轴，严重度是回答"缺了多少氯、缺了
多久"的正确轴。这与 Step 8b 从另一个方向得出的教训相同 —— **一份候选名单不点名产生它的度量就没有
意义** —— 现在把它应用到了登记表本身。

**但"两者都不正确"必须变成一条规则，不能停留在一种姿态。** 登记表的存在是为了驱动行动，所以如果它一边
输出一列 `control_measure`、一边声称不偏向任何一轴，它就已经默默地把破限轴变成了实际执行的那一个。
登记表的早先版本正是这么做的：它按 `risk_score_breach` 排序，并且完全从破限等级派生每一条控制措施。
现在规则是事先声明的：

```
主导等级       =  破限等级 与 严重度等级 中较高的那个
control_measure =  由主导等级给出
```

即**任何一条轴都不得单独降低一次行动**。逐轴的措施并列输出（`control_measure_breach`、
`control_measure_severity`），使理由保持可见，而登记表按 `risk_score_governing` 排序。

**在本基线场中这条规则目前与破限轴重合**，因为这里严重度等级从未超过破限等级 —— 主导等级在全部 92 个
节点上都等于破限等级。这个重合是被*测量并报告*的（`currently_equivalent_to_the_breach_axis`），不是被
假设的：上面的可达性表显示这个界限允许 1 个等级的反转，所以这条规则在一般情况下**不是空的**，而且在
真的发生反转的场上它会起作用。

**它仍然不是什么。** 两个乘积都以被标定的集合和情景 A 为条件；两者都不是测量。而且严重度轴继承了
`E[D]` 自身的盲区，这正是深度列存在的理由，必须与它一起读。

**取样优先级是一个分类模糊度指标，不是最优监测准则。** 它在"评估无法把一个节点归到任何一边"的地方
达到峰值，并按后果加权。它不含任何 Jacobian、不含相对现有六个监测点的冗余度、不含观测噪声模型、也不含
期望后验方差缩减，所以**绝不能**读作期望信息增益或传感器布置。把它命名为**分类模糊度取样指标**。它使用
**离散的后果得分（0–3），不是原始需求**：

```
priority(n) = consequence_score(n) · P_min(n) · [1 − P_min(n)]     按其最大值归一化
priority(n) = 0  当 demand = 0
```

所以它在 `P_min = 0.5` 处达到峰值 —— 即评估无法把节点归到任何一边的那些节点。

**产品声明（使用这个措辞）。** 输出是在所声明假设（水力固定、一阶动力学、示意性 Arrhenius / 老化乘子）
下、由网络模型给出的**以正式似然标定为条件的情景投影**。它**不是**传感器实时预报（没有做当日再条件化），
**不是**空间测量或地统计插值，**不是**现场预报或投加建议，**也不是**"水是安全的"这一陈述。余氯只是供水
安全计划中诸多预防屏障里的一个运行指标。

**复核触发条件（出现以下情况时本评估失效）：** 传感器 QA 失败或参比检查不一致；水力模型或需求分配被
修订；水源/处理工艺变更；水温超出 8–24 °C 的情景范围；预报有高温事件；管网施工改变了假定的管龄分布；
标定记录超过其批准有效期。

### 12.6 供结果 / 讨论章使用的结论

1. **温度显著抬高风险，但不会把网络推平。** `P_min>0.5` 节点数随 12 → 16 → 20 °C 从 21 → 28 → 29 上升；
   风险需求量从 8.0 % → 9.8 %；全网平均 `E[A]` 增长一倍以上（0.222 → 0.522 mg/L·h）。
2. **同温下的老化增加了一个空间上有选择性的增量**（`P_min>0.5` 节点 29 → 31；全网平均 `E[A]`
   0.5218 → 0.579 mg/L·h），集中在 old/average 管段控制供水路径的地方。**按 `P_min` 分类的集合**在所测
   `α` 范围内是稳健的（30 / 31 / 31 个节点，三者都是 69.4 L/s），而严重度量级随 `α` 缩放
   （`E[A]` 0.550 → 0.579 → 0.599）—— 应当把它作为一个胁迫区间报告，不是一个被测量的效应。
   *这里的"集合"指被归类为 `P_min > 0.5` 的节点，这是一个破限概率分类，**不是** Step 10 按 `E[A]` 排序
   的热点名单；两者是不同的产品，而 Step 8b 已经证明这类度量之间可以不一致。*
3. **发生升级的节点几乎全是未监测的**（**七个中的六个**，例外是被监测的节点 231），这是一个支持
   **信息导向的监测设计**、而不是笼统"增加监测"的论据。升级是 A 与 D 之间 `P_min` 风险等级的变化，
   所以这同样是一个破限概率的陈述。
4. **源头投加是一项不完整的控制措施。** +30 % 的入口投加量改善了每一个连续指标，但没有把风险需求量
   带回基线。在水力固定、一阶动力学和源头按比例缩放的理想化下，按 `r` 投加恰好等价于用 `C_crit / r`
   去检验；**它买不回停留时间。**
5. **情景图是标定区间之外的规划产品。** Arrhenius 形式、`T_ref` 和 `α_g` 都是假设；与 Step 11 的 LOO
   检查不同，这些投影**无法**对照留出的氯观测来验证。绝对严重度指标另外还依赖时域（配对预热检验，§12.4）。
6. **破限概率登记表和严重度登记表会分歧，而在本场中分歧是单向的。** 在同一后果轴上按事先声明的绝对
   分界给 `E[D]` 打分，会把 **59 个用户节点中的 10 个**放进*更低*的风险等级，**没有一个**放进更高的；
   这十个都必然破限（`P_min = 1.000`），但只持续 2.0–17.9 h，而且平均深度**差异显著，0.025–0.14 mg/L**
   —— 节点 125 在低于阈值时平均 0.175 mg/L，确实是边缘情况；节点 145 平均 0.060 mg/L，不是。在单个
   *prolonged* 等级内部，累积亏缺仍跨越 3.9 倍，所以一个严重度等级是关于时长的陈述，**绝不是关于量级
   的**。分歧的方向是**经验的，不是被蕴含的**：`E[D] ≤ T_window · P_min` 成立（92 个节点中 0 个违反），
   但它约束的是连续量而非分档得分，两者的尺度并未对齐 —— 它允许 1 个等级的反转，只有在 `P_min ≥ 0.80`
   时才禁止反转，而最接近的用户节点距离反转只有 **0.939 h** 的 `E[D]`。
7. **老化胁迫对破限概率几乎不可见，对严重度则清晰可见。** 用同一套绝对小时数给全部四个情景分档，
   *persistent* 用户（在 48 h 窗口中至少一半时间低于 0.2 mg/L）的数量从 A 到 D 是 **1 → 4 → 6 → 8**，
   而破限计数是 10 → 12 → 13 → **13**，在 C 和 D 之间饱和 —— 在 20 °C 时暴露集合的大部分已经处于
   `P_min > 0.8`，所以老化胁迫推不动它。一个只建立在破限概率上的登记表会报告"在热浪之上老化几乎没有
   增加什么"。**这是本日志中支持保留第二条轴的最清晰的理由**，而它之所以存在，正是因为严重度分界是用
   绝对小时数而不是分位数声明的（§12.5.1）。
8. **"等级变化"式的升级检验是必要但不充分的，原因有两个各自独立。** 十六个用户节点（52.3 L/s）在 A 和 D
   中都处于 `P_min ≈ 1`，所以它们的可能性等级不可能移动；节点 243 变成**整整 48 h 窗口**低于阈值，
   节点 15（全网最大用户）增加了 11.6 h，两者都没有被标记。`max(破限, 严重度)` **救不了这个** —— 它会
   **饱和**，而这是一个与当初采用它的理由不同的性质。另外，乘法矩阵**把一个次要用户封顶在 `medium`**
   （得分 `5 × 1 = 5`），所以**有 20 个节点（17.46 L/s）**无论变得多严重都永远不可能被归为 `high`。
   **这是 `可能性 × 后果` 这种形式本身的性质。** 在一个饱和或被封顶的节点上，升级必须在 `ΔE[D]` 和
   `ΔE[A]` 上读（§12.3）。由于两个乘积都不是那个"正确"的，登记表对两个等级中**较高**的那个采取行动，
   这是一条事先声明的规则，它目前在这里与破限轴重合，而且这个重合是被报告的而不是被假设的（§12.5.1）。

## Step 13 —— 已知答案检验：系数真的是按我们设定的那样实现的吗？（Priority-2 #7）

本日志中每一个数字都建立在一个从未被直接检验的假设上：一个以 `1/day` 或 `m/day` 写下的系数，除以 86400
交给 WNTR 之后，到达 EPANET 时**仍是那个系数**。评审在所报数字中发现了一处单位错误（§3.4），所以这个
假设并非不言自明地安全。这就是评审要求的单管解析检验（`step13_known_answer.py`）：一个水库、一根 1000 m
长、0.3 m 直径的管、恒定 0.05 m³/s 的需求、`C0 = 1.0 mg/L`、24 h。

**分支 1 —— 纯体相衰减对照解析解。** 在没有壁面反应时，锋面通过之后末端的浓度是精确的。

**公式**：

```
C = C0 · exp(k_b · t_res),     t_res = L / v
```

**性质**：

- 单位：换算后 `k_b` 是 1/s，`t_res` 是 s，`C` 是 mg/L。
- 这个检验是字面意义上的*单位*检验：一个错误的换算因子会在每个 `k_b` 上让 `C` 产生**相同比例**的变化。

| `k_b` (1/day) | `t_res` (h) | EPANET `C` | 解析 `C` | 相对误差 |
| --- | --- | --- | --- | --- |
| −0.50 | 0.3927 | 0.991846 | 0.991852 | 6.7 × 10⁻⁶ |
| −1.00 | 0.3927 | 0.983744 | 0.983771 | 2.7 × 10⁻⁵ |
| −2.00 | 0.3927 | 0.967699 | 0.967805 | 1.1 × 10⁻⁴ |

最差相对误差 **1.1 × 10⁻⁴**，容差是 10⁻³。误差**随衰减量增大而增长**，跨越 `k_b` 的四倍范围 —— 这是
水质求解器时间离散化的特征；一个错误的换算因子给出的会是一个**恒定的相对偏移**。所以换算和单位都得到
确认。

**分支 2 —— 壁面衰减：单调性和一个界限，不是精确值。** EPANET 的一阶壁面反应同时受传质限制，通过一个
总速率常数

```
k_overall = k_b + (4 / D) · (k_w · k_f) / (k_w + k_f)
```

所以在不知道传质系数 `k_f`（它取决于流态）的情况下，`C` 无法仅由 `k_w` 预测。**可以断言的东西**在
`k_b = −0.5` 1/day、`k_w ∈ {0, −0.1, −0.5, −1, −2}` m/day 上做了检查：`k_w = 0` **精确复现**纯体相运行，
`C` 随 `k_w` 增强**单调下降**，且 `C` 始终高于"壁面项取 `(4/D)·k_w`"的无 `k_f` 极限。三条全部成立。
这足以确立壁面系数是按预期的符号和尺度施加的，而且它就是这样陈述的，**不是**作为一个精确解析吻合。

**分支 4 —— 浓度单位，对照 WNTR 自己的转换器。** 分支 1–3 检验的都是*时间*换算，那在继承的材料里有
文档且从一开始就是对的。*浓度*换算在 Step 15 之前**根本没有被施加**，而这里没有任何东西能抓到它：在
一阶动力学下解析检验是一个**比值**，所以在两种标度下它都通过。因此本分支把单位钉在
`wntr.epanet.util.to_si` / `from_si` 上，而不是钉在我们对它们的信念上 ——
`to_si(1.0 mg/L) = 0.001 kg/m³`，`from_si(1.0 kg/m³) = 1000 mg/L`，`wq_common` 里的辅助函数与两者一致。
分支 5 随后把写出的 `.inp` 读回来，把那个描述反复出错的不对称性钉住：源是**换算后**写入的
（`0.001 kg/m³ → River 1.0`），而 `TOLERANCE` 是**原样**写入的（`1e-05`），所以 EPANET 按 mg/L 读取
这个容差。一阶系数不带质量单位，这正是分支 1–3 不受分支 4 所要防范的那个错误影响的原因。

**分支 3 —— 换算辅助函数本身。**
`per_day_to_per_second(−1.0) = −0.0000115741 per second`，即恰好是 `−1/86400`。

全部检查通过。论文里应当有一段陈述这件事：**工具链按预期实现了体相系数的尺度，并以预期的符号和物理上
有界的单调衰减施加壁面反应；壁面那一分支在传质限制下**不是**对精确数值壁面系数尺度的解析验证**。标定
结果关乎的是反问题，而不是一个单位错误。

## Step 14 —— 重复噪声标定：偏差、CRLB 一致性、区间覆盖率

本日志别处引用的每一个正式后验（除了本身已对噪声取平均的那些步骤）都来自**一次**噪声实现。那足以说明
后验很窄、且其宽度接近 Case-A CRLB，但它无法确立真正决定"一个估计量是否被校准"的两条性质：

- **偏差** —— 后验均值平均而言是否落在真值上？
- **覆盖率** —— 一个名义 90%/95% 的区间是否大约有 90%/95% 的时间包含真值？

两者都是重复抽样的陈述。8192 个成员的候选库与噪声无关，所以本节**不花费任何 EPANET 运行**：只重抽观测
（`step14_repeated_noise.py`，`N = 100` 个种子从 `20000` 起，刻意与别处使用的 `42…71` 区块不相交）。

**共享库的限定条件（它约束整节）。** 每一次实现都是对**同一个** Sobol 预测库加权，所以各次实现之间的
蒙特卡洛误差不是独立的，而一个锐利的似然只能通过其 ESS 来分辨区间端点。正式 ESS 的中位数 / p5 / 最小值
约为 **158 / 122 / 113** —— 对所报告的覆盖率是够用的，但并不宽裕。

头条校准结果（old / average / new）：经验 SD / CRLB ≈ 1.04 / 1.06 / 1.12；名义 90% 区间覆盖
0.89 / 0.88 / 0.85。

**主分析 —— 正式截尾**（100/100 有效）：

| 系数 | 真值 | E[后验均值] | 偏差 | 偏差/经验 SD | 均值的经验 SD | 运行内 SD | 运行内/经验 | CRLB | 经验/CRLB | cov90 | cov95 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| old | −1.00 | −1.0055 | −0.0055 | −0.06 | 0.0981 | 0.0960 | 0.98 | 0.0947 | 1.04 | 0.89 | 0.97 |
| average | −0.10 | −0.1021 | −0.0021 | −0.15 | 0.0144 | 0.0137 | 0.95 | 0.0135 | 1.06 | 0.88 | 0.96 |
| new | −0.05 | −0.0498 | +0.0002 | +0.02 | 0.0089 | 0.0079 | 0.89 | 0.0080 | 1.12 | 0.85 | 0.91 |

**对照 —— 非正式 GLUE**（阈值 0.107）：偏差/经验 SD 最大到 −1.76（`average`）；运行内 SD 是正式宽度的
**约 2.6–2.9 倍**（0.2489 / 0.0393 / 0.0226 对 0.0960 / 0.0137 / 0.0079 m/day，对应 old / average / new）；
cov90 ≈ 0.98–0.99。**高覆盖率是用宽度买来的，不是用准确度买来的。**

重复噪声标定

结论：

1. **在合成的生成模型下，正式后验均值基本无偏** —— 每一个偏差都只是估计量自身抽样 SD 的一个小零头。
2. **正式后验的离散度与 Case-A CRLB 局部一致**（经验/CRLB ≈ 1.04–1.12；运行内 SD / CRLB ≈ 1.00–1.01）。
   这是一次**一致性检查，不是频率学派有效性的证明**：两个量使用的是同一个模型、同一个真值和同一套误差
   假设。
3. **名义区间接近校准**：old 和 average 在 90%/95% 上都接近；`new` 在 90% 上略微欠覆盖（0.85），这与它
   较小的 ESS 足迹和共享库的粗糙度是一致的。
4. **非正式对照不是一个被校准的紧致区间** —— 它是靠宽出数倍来过覆盖的，这与 Steps 1–3 和 7 中诊断出的
   低效是同一件事。

## Step 15 —— 氯浓度单位曾经差了 1000×，以及它改变了什么、没改变什么

**这不是一条评审意见。** 它是在修订基本完成之后由自查发现的，而且是本项目历史上最大的单一错误：仓库中
每一个氯浓度，在它的整个生命周期里，一直到本节为止，都处在一个**高出 1000 倍的标度上**。

**错在哪里。** WNTR 的 Python API 内部以 **kg/m³** 存储浓度。`options.quality.inpfile_units = "mg/L"`
只管 `.inp` 如何被读写 —— 它**不改变**通过 API 赋的值的含义。因此，本想表达"1 mg/L"而赋值
`initial_quality = 1.0`，实际上让 EPANET 模拟的是 **1000 mg/L**，而把 `run_sim()` 的输出按 mg/L 读回来
又在出口处重复了一遍这个错误。直接测量显示，修正前 WNTR 写给 EPANET 的文件里是这样的：

```
[QUALITY]                       [OPTIONS]
River      1000.0               QUALITY    Chlorine mg/L
Lake       1000.0               TOLERANCE  0.01
1           500.0
```

所以源是 1000 mg/L，水箱是 500 mg/L，传感器噪声 σ 是 100 mg/L，而"0.2 mg/L 的运行阈值"是 200 mg/L。
修正之后，同样的探针显示的是 `River 1.0`、`1 0.5`、`TOLERANCE 1e-05`。

**它为什么能存活这么久 —— 三个原因，而且没有一个仅仅是粗心。**

1. **一阶动力学对 C 是线性的。** 浓度场精确随源缩放，而 σ 和风险阈值也表达在同一个错误标度上，所以
   **分析所依赖的每一个比值都被保住了**：无论哪种标度，σ/C₀ = 0.1 且 C_MIN/C₀ = 0.2。**没有任何内部检查
   会失败。**
2. **反应系数不受影响，所以已知答案检验通过了。** `k_b` 是 `1/时间`，一阶 `k_w` 是 `长度/时间`；两者都
   不带质量单位，所以这个因子不可能传播进去。对照 WNTR 写出的文件验证过：`GLOBAL BULK -0.5000` 和
   `WALL -3.2808 / -0.3281 / -0.1640 ft/day`，正是预期的 −0.5 day⁻¹ 和 −1.0 / −0.1 / −0.05 m/day。
   Step 13 的解析分支因此全程都以 10⁻⁴ 的精度通过。
3. **这个因子其实早就被发现过，只是被误诊了。** 继承下来的入门 notebook 把"一个**零阶**全局体相系数
   需要 `×1000`"（`ZERO_ORDER_BULK_CAL = 1000.0`）记录为一个实测事实。**那就是同一个 kg/m³ 事实**：
   一个零阶系数带有 `质量/体积/时间` 的量纲，所以它会把这个因子暴露出来。但它被记成了零阶体相的一个
   怪癖，而不是浓度单位的一个性质，所以它从未被应用到浓度本身 —— 而在一阶下，浓度上的这个错误**没有
   任何症状**。**这个因子唯一可见的地方，正是它唯一被打补丁的地方。**

### 15.2 容差是第二个、独立的改动 —— 必须这样陈述

这个修正有两个部分，而且它们**不是同一类改动** —— 本节的早先版本把第二个称作单位换算，那是错的。

EPANET 的水质 `TOLERANCE` 是一个**绝对**浓度，低于它两个水团被视为相同。与浓度不同，WNTR **不**换算它：
`write_inpfile` 把 `options.quality.tolerance` **原样**放进 `.inp`，而 EPANET 按文件所声明的浓度单位读取。
把写出的文件读回来（Step 13 分支 5）可以并排看到这两种行为：

```
[OPTIONS]  QUALITY   Chlorine mg/L
[OPTIONS]  TOLERANCE 1e-05          <- 原样写入  -> EPANET 按 1e-5 MG/L 读
[QUALITY]  River     1.0            <- 由 0.001 kg/m^3 换算后写入
```

所以 `QUALITY_TOLERANCE = 1e-5` 就是 **1e-5 mg/L**，把它叫作"1e-5 kg/m³"或"内部表示的 0.01 mg/L"在两个
方面都是错的。它比 **EPANET 的 0.01 mg/L 默认值严格 1000 倍**，而这是一个**必须被声明为主动选择**的
数值决定。

**为什么选这个值。** 被取代的配置是用 0.01 的默认值去跑一个 1000 mg/L 的源 —— 容差/源比值是 1e-5。
在修正浓度的同时把 0.01 留着，就会变成 0.01 对 1 mg/L，比值 1e-2：一个比此前所有已发表结果所依据的
求解器**粗三个数量级**的求解器。**保持这个比值不变**，正是让 Step 15 能把修正后与被取代的运行当作
**同一个数值实验**来比较、并把它们的一致性**完全归因于单位**的原因。更严的容差**很可能**同时也更
*准确* —— 它把拉格朗日输运解析得更细 —— 但那**不是这里在做的论证**，本日志也不声称它：论证的是
**可比性**，而代价是运行时间。

**公式** —— 换算只在模型边界施加，别处不做：

```
内部 (WNTR/EPANET)  =  报告值 (mg/L) / 1000        build_model，入口
报告值 (mg/L)       =  内部值 × 1000               run_model / simulate_chlorine，出口
QUALITY_TOLERANCE   =  1e-5 mg/L（选定的，不是换算的；EPANET 默认 0.01 mg/L）
```

**性质**：

- `wq_common` 之外的一切都以 mg/L 为单位，所以没有任何 step 脚本需要改动：`σ = 0.1` 和 `C_MIN = 0.2`
  读起来和一直以来一样，**而现在它们是真的**。
- AGE 运行是豁免的：它的"初始水质"是一个时间，不是浓度。

### Step 15 —— 在 256 个领先 Sobol 候选上实测的影响

在完全相同的候选上跑三个分支（`step15_unit_equivalence.py`）：**legacy**（被取代的配置，它的原始输出
正是旧缓存所存、而本日志曾按 mg/L 引用的东西）、**corrected**（当前）、以及 **units_only**（单位修好、
容差留在 0.01 —— 把修正做错的那种做法，作为反事实保留）。

| 对比 | 最大绝对差 | 最大相对差 | 低于 0.2 的点数 | 低于阈值小时数不同的单元格 |
| --- | --- | --- | --- | --- |
| corrected vs legacy | 1.19 × 10⁻⁷ mg/L | **2.3 × 10⁻⁷** | 79391 → 79391 | **23552 个中 0 个** |
| units_only vs legacy | 2.09 × 10⁻² mg/L | **17.8 %** | 79391 → 79301 | **23552 个中 440 个** |

所以这个修正**做对了**的话，所报告的浓度场**在 2.3 × 10⁻⁷ 相对误差内保持不变** —— 就是浮点精度。而
**不带容差**地做，它会**引入 17.8% 的最大相对误差**，并移动 1.9% 的风险时长单元格。第二行正是"容差是
这个修正的一部分、不是事后补丁"的理由。

### Step 15b —— 在完整库上、以及在本日志上的验证

**本节过去引用的是没有任何 artifact 支撑的数字。** 下面三条最初是由修正过程中的一次性脚本产生的，
这违反了本仓库自己的规则 —— 每个数字都必须来自一个脚本和一个具名 artifact。`step15b_full_regression.py`
现在执行完整的比较并写出 `step15_full_regression.json`。**跑它不仅仅是确认了旧的三条 —— 其中两条是错的**，
更正后的数字在下面。

这个比较有两半，可复现性不同。**完整库**那一半是**实时的**：修正臂从 `baseline_cache/baseline.npz` 读取
—— 也就是流程其余部分实际消费的那个缓存，所以这检查的是**被存储的那个 artifact**而不是它的一份新副本
—— 而只有 legacy 臂被重新模拟（8192 次 EPANET）。**artifact** 和**日志**这两半是**历史性的**，从两个
被记录的 git 提交读取：`64ec7d3`（修正之前的最后一个状态）和 `3427a9d`（记录该修正的那个状态）。它们
**无法**从当前工作树重新导出，因为后续工作 —— 需求 pattern 修正、登记表的严重度轴 —— 合理地改动了后来
的数字。这两个 SHA 存在 artifact 里，而**如果历史被重写，脚本会报错退出而不是安静地什么都不报告**。

- **`baseline.npz`，全部 8192 个候选**：`C_all` 最大绝对差 `1.2 × 10⁻⁷ mg/L`，最大**相对差 2.3 × 10⁻⁷**；

  两个分支由同一套 Sobol 抽样驱动，其 SHA-256 被记录，所以一个被悄悄重新生成的设计是可检测的。
  *（早先那一条为其中第二和第三项引用了 9.2 × 10⁻⁸ 和 1.7 × 10⁻⁷；两个都与被跟踪脚本的实测值不符。）*
- **26 个 artifact，4915 个数值字段**（3 个作为运行时长和哈希被排除）：**34** 个字段的相对变动超过
  1e-4 —— 不是早先那条所声称的五个。相对筛选在这里**严重高报**，所以它们按量本身的大小分档：4 个的
  量级低于 1e-4（一个本身约 1e-6 的数字的相对变动，就是模拟的一个 ulp），21 个的绝对变动小于 1e-4，
  9 个大于。这 9 个里最大的是一个**优化器迭代计数**（`n_epanet_evaluations` 7770 → 7792）；其余是有限

  五位小数上变动的 Kendall τ。**没有任何估计值、区间、排序或风险数字在其中。** 这正是**数值分辨率**
  变化的预期特征：移动的是度量收敛性的机器，不是结果。
- **本日志，在 `3427a9d` 处有 3582 个数字**（在 `64ec7d3` 处 3473 个；两个序列用 `difflib` 对齐，所以
  插入的散文不会把后面每个数字都报成改变）：**三个**数字改变，不是两个，另加四处插入 —— 那正是新增的
  Step 15 文本本身。这三个是：`0.991845 → 0.991846`（单管解析检验中的 EPANET 值，第六位小数）、
  `6.8 → 6.7 × 10⁻⁶` —— 也就是*同一个值自身的相对误差*，即同一个事实在同一张表里出现两次而只被算作
  一次 —— 以及 `7770 → 7792` 次 EPANET 评估，一个迭代计数。
  *（早先那一条里的"1720 个被检查的数字"是校验器**能匹配到 artifact** 的数字个数，不是日志里数字的
  总数；两者被混为一谈了。）*

**这意味着什么，要谨慎陈述。** 这个修正改变的是这些数字的*含义*，不是这些数字。本日志中每一个参数、
可辨识性、结构误差、传感器偏置、`k_b`、风险和情景结论都**逐字成立**，而且这是**被测量出来的，不是被
论证出来的**。曾经错、现在对的是**物理解释**：传感器 σ、`0.2 mg/L` 阈值、投加水平，以及风险表格里的
每一个 `mg/L` 和 `mg/L·h`，在本节之前都是关于一个 **1000 mg/L 系统**的陈述。任何依赖绝对浓度的工程
论断 —— 所需传感器精度、运行阈值、投加评估 —— 在修正之前**不被支持**，在修正之后**被支持**。

**防止它回来。** `step13` 的分支 4 把浓度单位钉在 WNTR 自己的 `to_si`/`from_si` 上，而不是钉在我们对
它们的信念上；**分支 5 把写出的 `.inp` 读回来**，断言本节散文最初写错的那个不对称性：源是换算后写入的
（由 `0.001` kg/m³ 得到 `1.0` mg/L），而 `TOLERANCE` 是原样写入的（`1e-05`，被 EPANET 按 mg/L 读取）。
单位约定和容差也都进入了溯源配置哈希，所以在不同约定下建立的缓存不可能再被误认为是这一个。

**还有一个标签是错的，而且修正它是刻意推迟的。** 被哈希的配置把容差记录在键名
`quality_tolerance_kg_m3` 下。这个*值*（`1e-5`）是正确的，也正是本日志中每个结果所使用的；只有键**名字**
里的单位是错的 —— 它是 mg/L。

重命名它会改变 `config_sha256`（`c97826ac…` → `607f2034…`）。不会有任何已存结果因此变错，因为没有任何
step 的 JSON 内嵌那个哈希 —— 但六个 `*.key.json` 文件届时会记录一个被取代的配置，于是被键控的数组
（`step4d`、`step7b`、`step7c`、`step8b`）会在下次使用时**静默地冷重建**，而 `step9` 会在 `step7c` 重跑
之前抛错。那是一次输出在数值上与现有结果**完全相同**的重跑。因此它**不**作为一项独立任务来做；它属于
干净树发布重跑的一部分，而后者本来就另有必要。把它记在这里，是为了让这个不一致不至于是无声的 ——
这正是"写下来"而不是"付两次代价"的意义。
